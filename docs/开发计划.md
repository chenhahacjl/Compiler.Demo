## 阶段 0 — 修复 x86 Native 崩溃

**目标**：修复 hello-x86.exe 在管道输入 "123\r\n" 时的崩溃（0xC0000005）。

**方法**：黑盒对照 —— 不靠猜测，用等价 C 程序 + 成熟编译器验证行为。

| 步骤 | 动作 |
|------|------|
| 0.1 | 安装 TinyCC + MinGW-w64（含 objdump） |
| 0.2 | 编写与 Runtime.X86 语义等价的 C 程序（input/print/字符串处理） |
| 0.3 | `objdump -d -Mintel` 对照反汇编：栈帧、栈检查、input 路径、字符串布局、调用约定、导入表 |
| 0.4 | 同输入 "123\r\n" 运行 tcc/gcc 版本，确认行为 |
| 0.5 | 修复 `src/Cocoa/CodeAnalysis/Emit/Native/Runtime/Windows/X86/Runtime.X86.cs` |
| 0.6 | 回归：runx86.ps1 exit=0、stdout 完整；x64 同步验证 |

**验收标准**：hello-x86.exe 管道输入不再崩溃；x86/x64 双平台基线测试全绿。

## 阶段 1-3 — IR 层

**目标**：在绑定树（Lowerer 输出）与 IAssembler 之间插入统一 IR，使 x86/x64 后端共享同一中间表示。

### 阶段 1：IR 设计

- 三地址码（每个指令最多一个目的寄存器 + 两个操作数）
- 虚拟寄存器（无限，由后端分配物理寄存器/栈槽）
- IR 指令集覆盖：常量加载、mov、算术/逻辑/比较、分支/标签、call、栈操作、内存读写（字符串/数组）
- IR 打印器（文本形式，用于测试与 .cod 输出）

### 阶段 2：Native 后端 IR 化

- 新增 IR → IAssembler 后端（x86/x64 共用）
- `NativeCodeEmitter` 改为绑定树 → IR Lowerer + IR → IAssembler
- 严格复制现有 ABI：调用约定、栈布局、参数传递、返回值（eax/rax）语义

### 阶段 3：语义对齐

- 与现有 x86/x64 输出逐指令对照（同一 .co 文件双后端输出相同语义）
- 既有 Native 测试全部保持绿色
- 为阶段 4 的运行时 IR 化提供基础

**验收标准**：IR 层就绪，Native 输出与当前实现行为一致；x86 崩溃测试通过。

---

## 阶段 4 — 运行时 IR 化

**目标**：把内建运行时函数（Runtime.X86.cs / Runtime.cs 中的手写汇编/托管实现）统一为 IR 生成。

| 顺序 | 函数 |
|------|------|
| 1 | `Input`（崩溃相关，优先） |
| 2 | `WriteStr` |
| 3 | `Alloc` / `CopyChars` / `Concat` |
| 4 | 其余（print/exit/random 等） |

- x86/x64 运行时合并为一份（平台差异收敛到 IR 指令选择层）
- **验收标准**：Runtime 双平台单实现，全部测试通过。

---

## 阶段 5 — IL 路径自研（零第三方依赖）

**目标**：移除 Mono.Cecil 与 Mono.Options，IL 路径完全自研。

| 组件 | 说明 |
|------|------|
| IL 编码器 | 指令字节序列生成（opcode + 操作数 + 分支 fixup） |
| ECMA-335 元数据写入器 | 表、堆（#Strings/#Blob/#GUID）、AssemblyRef/TypeRef/MethodDef 等 |
| 托管 PE 写入器 | 复用 PEFile 基础设施（CLR 头 + 数据目录） |
| Emitter 重写 | 现有 Mono.Cecil 调用全部替换 |

- 仅保留 `System.Collections.Immutable` 依赖
- **验收标准**：IL 路径输出经 `dotnet` 运行验证，互操作测试全绿；csproj 中第三方包清零。

## 阶段 6 — 语言扩展 + 互操作 + 输出格式 + 项目系统

### 6a. 语言功能扩展

| 特性 | 说明 |
|------|------|
| `record` | 值/引用语义记录，自动 Equals/ToString 等 |
| 动态数组 | 长度运行时可变（区别于固定数组） |
| `byte[]` | 字节数组类型（互操作基础） |
| 字符串增强 | 索引、子串、比较运算 |
| `enum` | 枚举类型 |
| 多文件模块 | 文件间符号可见性管理 |
| 泛型 | 函数/类型级泛型 |
| `import` / `export` | 见 6c/6f |

### 6b. 输出格式系统（见 `docs/输出格式.md`）

```
coc build -p foo.coproj -f exe|dll|cod
```

| 格式 | 说明 |
|------|------|
| `exe` | 现状（Native/IL 可执行文件） |
| `dll` | 写侧导出表 + 重定位表（x86 HIGHLOW / x64 DIR64），`export fn` 标记导出 |
| `cod` | IR 序列化（阶段 1 的 IR 文本/二进制格式） |

### 6c. 互操作（见 `docs/互操作手册.md`）

| 目标 | 路径 | 位置 |
|------|------|------|
| native DLL | `import kernel32.dll` → 导入表消费（与现状 exe 同机制） | 阶段 6 |
| .NET DLL | IL 路径：AssemblyRef 直通 | 阶段 6 |
| `.cod` 库 | IR 加载合并编译（依赖清单：.NET 程序集引用 + native 导入传递） | 阶段 6 |
| Native 路径 .NET | CLR Hosting | 阶段 9（可选） |

### 6d. 项目系统（见 `docs/项目格式规范.md`）

- `.coproj` / `.cosln`：**自定义轻量文本格式**（非 JSON）
- CLI：`coc build -p foo.coproj`、`coc build -p sol.cosln`
- 增量构建：源文件哈希缓存，未变更项目跳过编译

### 6e. 其他

- `export fn` 导出语法（dll 输出时生成导出表）

**验收标准**：exe/dll/cod 三种输出可用；native/.NET/cod 三类导入可编译运行；项目系统支持增量构建。

## 阶段 7 — 编译器自举重写

**目标**：用 Cocoa 语言（阶段 6 之后的功能）重写编译器本体。

- 组件顺序：Lexer → Syntax → Parser → Binder → Lowerer → IR → 后端
- Native 与 IL 两条路径都要自举
- 阶段 5 的自研 IL 编码器/元数据写入器在 Cocoa 中重写（递归依赖解耦：编译器只依赖阶段 6 语言特性）

**验收标准**：Cocoa 版编译器可编译全部测试用例。

---

## 阶段 8 — 自举验证

```
Stage 0: 现 C# 编译器编译 Cocoa 编译器源码 → B0
Stage 1: B0 编译同一源码 → B1
Stage 2: B1 编译同一源码 → B2
验证: B1 ≡ B2（输出等价）
```

**验收标准**：B1 ≡ B2，且 B2 能编译真实项目。
