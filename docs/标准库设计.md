## 1. 目标与范围

把硬编码的内置函数演进为**标准库体系**：功能层（per-backend 原语）与逻辑层（Cocoa 源码标准库）分离，命名空间限定访问，支持重载，`.cod` 程序集以外部文件交付（仿 .NET 引用模型）。

**范围**：`print`/`input`/`random` 演进为功能层内部调用原语（6e-M17 起 `src/stdlib/System.Core/` 内 `System.Runtime` syscall 声明）；新增 Math/String/Array 三模块逻辑层；用户 `.cod` 库改为命名空间-only 访问；`.cod` 格式 v1→v2。

## 2. 分层模型：功能层 / 逻辑层

| 层 | 定义 | 归属 | 三后端映射 |
|----|------|------|-----------|
| **功能层** | 语言不可约的后端能力原语（I/O、随机、未来硬件数学） | **6e-M17 起为可声明的内部调用层**：`src/stdlib/System.Core/Runtime.co` 内 `namespace System { class Runtime { syscall function … } }`，编译器内建嵌入；仍经 `BuiltinKind` 分发（`syscall` 声明命中内置表复用 singleton） | Evaluator：C# 直接实现；IL：.NET API（`IlFramework` 集中方法引用）；native：自研运行时函数（`RuntimeEmitterIR`） |
| **逻辑层** | 可用语言特性表达的标准库函数 | Cocoa 源码 → `.cod`（`src/stdlib/`，`namespace System`） | 三后端零改动（语义层 BoundProgram 合并） |

**边界判定**：能被现有语言特性（算术/字符串/数组/控制流）表达的 → 逻辑层；需要后端特殊服务（I/O/随机/硬件指令）的 → 功能层。

**功能层原语清单（现状 + 扩展位）**：

| 原语 | 签名（syscall 声明，6e-M17） | Evaluator | IL（.NET） | native |
|------|------|-----------|-----------|--------|
| `WriteLine` | `(text: any): void` | `Console.WriteLine` | `Console.WriteLine(object)` | 运行时 `PrintString`/`PrintInt`/`CharToString`/`DoubleToString`（按参数类型分派） |
| `Write` | `(text: any): void` | `Console.Write` | `Console.Write(object)` | 运行时 `WriteString`/`WriteInt`（6e-M19） |
| `ReadLine` | `(): string` | `Console.ReadLine` | `Console.ReadLine` | 运行时 `Input` |
| `ReadKey` | `(intercept: bool): char` | `Console.ReadKey(...).KeyChar` | `Console.ReadKey(bool)` + `get_KeyChar`（box+callvirt） | 运行时 `ReadKey`（ReadConsoleInputW + INPUT_RECORD，6e-M19） |
| `Random` | `(max: int): int` | `Random.Shared.Next` | `new Random().Next(int)` | 运行时 `Random`（xorshift32） |
| `Sleep` | `(ms: int): void` | `Thread.Sleep` | `Thread.Sleep(int)` | kernel32 `Sleep`（6e-M17） |
| `TickCount` | `(): int` | `Environment.TickCount` | `Environment.get_TickCount` | 运行时 `TickCount`（GetTickCount/GetTickCount64，6e-M17） |
| `Exit` | `(code: int): void` | `Environment.Exit` | `Environment.Exit(int)` | 运行时 `ExitProcess`（6e-M17） |
| `Sqrt` | `(x: double): double` | `Math.Sqrt` | `Math.Sqrt`（JIT intrinsic） | IR `FSqrt` → `sqrtsd`（SSE2，6e-M19） |
| `Floor` | `(x: double): double` | `Math.Floor` | `Math.Floor` | IR `FFloor` → `roundsd imm=1`（6e-M19） |
| `Ceiling` | `(x: double): double` | `Math.Ceiling` | `Math.Ceiling` | IR `FCeiling` → `roundsd imm=2`（6e-M19） |
| `Truncate` | `(x: double): double` | `Math.Truncate` | `Math.Truncate` | IR `FTruncate` → `roundsd imm=3`（6e-M19） |
| `Round` | `(x: double): double` | `Math.Round` | `Math.Round` | IR `FRound` → `roundsd imm=0`（banker's，6e-M19） |
| `Beep` | `(frequency: int, duration: int): void` | `Console.Beep` | `Console.Beep(int,int)` | kernel32 `Beep`（6e-M19） |

## 3. 类型映射表（统一 ABI）

三后端的类型表示（对齐 .NET P/Invoke 编组表）。功能层原语签名只走这些类型，保证跨后端一致。

| Cocoa 类型 | Evaluator（C#） | IL（.NET） | native（Windows） |
|-----------|----------------|-----------|-------------------|
| `int` | `int` | `System.Int32`（4B） | 4B dword（直通） |
| `byte` | `byte` | `System.Byte`（1B） | 1B（movzx 零扩展） |
| `bool` | `bool` | `System.Boolean` | 4B 0/1（BOOL 语义） |
| `char` | `char` | `System.Char`（2B UTF-16） | 2B UTF-16 |
| `double` | `double` | `System.Double`（8B） | 8B（SSE，x86 双 32 位槽） |
| `string` | `string` | `System.String` | `[len:4][UTF-16 chars]` |
| `T[]` | `T[]` | `System.T[]`（SzArray） | `[len:4][elements]` |
| `any` | `object` | `System.Object`（装箱） | 4/8B 对象引用 |
| `enum` | 底层 int | `System.Int32` | 4B |

**blittable vs 非 blittable**（对齐 .NET 概念）：
- 直通（blittable）：`int`/`byte`/`double`/指针——内存布局一致，零转换。
- 转换（非 blittable）：`bool`（扩展 4B）、`char`（按 UTF-16）、`string`（native 是长度头+UTF-16，与 `WriteConsoleW`/`MessageBoxW` 的 `LPWSTR` 天然一致）。
- 数组参数（extern 穿越，后续）：指向元素首地址（native 需跳过 4B 长度头）——本轮 stdlib 不做 extern 穿越，机制保留扩展位。

## 4. 命名空间模型

**三种访问形式**（stdlib 函数为命名空间限定，不裸注入全局作用域）：

```cocoa
System.Math.Max(3, 5)          // 全限定
using System;                   // using 根命名空间 → 模块名可解析
Math.Max(3, 5)
using System.Math;              // using 模块命名空间 → 裸名可解析
Max(3, 5)
```

**规则**：
- 标准库 `namespace System { namespace Math {...} namespace String {...} namespace Array {...} }`——函数 `Namespace` = `System.Math` 等。
- `BindMemberCallExpression`：命名空间函数解析**先于**类静态方法路径（避免 `System.Math.Max` 被 .NET 真实 `System.Math` 劫持）。
- `BindCallExpression`：裸名失败后遍历 `_usingNamespaces` 查命名空间函数。
- **用户 `.cod` 库同样命名空间-only**（去掉裸注入），消费方需 `using MyLib;` 或 `MathLib.Add(...)`。
- 用户程序自己的顶层函数仍裸名（无冲突）；用户可定义同名函数覆盖 using 解析（局部作用域优先）。

## 5. 函数重载

**注册**：同 `(name)` 不同参数签名放行；同签名（含仅返回值不同）→ `ReportSymbolAlreadyDeclared`。

**解析算法**（`BindCallExpression` + `BindMemberCallExpression`）：
1. 收集同名候选（作用域链裸名 + using 命名空间 + 命名空间限定）。
2. 参数量 == 实参数过滤。
3. 逐一检查隐式转换可行性（`Any` 通吃；显式转换不参与重载解析）。
4. 计分：`identity`=0、`implicit`=1，取总分最低为最佳匹配。
5. 唯一最佳 → 绑定；无可行 → 无匹配重载诊断；并列最低 → 歧义诊断（新 `ReportAmbiguousInvocation`）。

**示例**：`Max(3, 5)` → `Max(int,int)`（score 0）胜 `Max(double,double)`（score 2）；`Max(3.0, 5.0)` → int 不可行（显式）→ double。

**发射唯一名**（IL 元数据方法名）：
- 顶层函数方法名 = `EmitName`（`ns + "." + name`，如 `System.Math.Max`）。
- 同 `(ns, name)` 组 >1（重载）→ 追加参数类型后缀保证唯一。
- native 调用按对象引用（`_functionLabels`/`_functionMap`），天然支持重载，无改名。

## 6. `.cod` v2 序列化格式

**格式变更**：`(fn id name [ns] retTypeId isExtern dll cc paramCount ...)`——`fn` 增加 `ns` 字段（函数命名空间）。

**版本策略**：`Version` 1 → **2（硬升级）**。读侧校验版本，不匹配报"库需重新编译"。旧 `.cod` 产物（如 `samples/CodLibrary`）重新构建。

**重载支持**：天然——函数按 id 序列化、调用按 id 引用，同名字不同签名的函数只是多个符号。

**消费**：命名空间-only 注入（`InjectCodSymbols` 不再裸注入），函数按 `(ns, name)` 注册进作用域命名空间表，支持重载列表。

## 7. `.cod` 中间库性质（一次编译，多端消费）

`.cod` 存的是**语义层 `BoundProgram`（降级绑定树 + 符号表）**，不是 native 三地址码、也不是 IL——后端无关，**一次编译，三后端（Evaluator/IL/native）消费**。对应 .NET 的 IL 程序集概念：C# 编译成 IL（后端无关中间产物），JIT/AOT 在运行时/部署时按平台再编。

| 维度 | 机制 | 说明 |
|------|------|------|
| **格式版本** v1/v2 | 版本校验 + 重编 | 一次重编（跟消费方无关）；v2 加 `fn` 的 ns 字段，旧库读侧报"需重新编译" |
| **`requires`**（any/dotnet） | 消费端**编译期校验门** | 含 .NET API/OOP 的库 `requires:dotnet` → native 消费端拒绝；纯函数库 `requires:any` → 双后端可用。**不是单独编译，是验收** |
| **平台 / native 导入** | 清单记录 + 消费端发射 | `import kernel32.dll` 记入 manifest；native 消费端按目标平台（x86/x64）发导入表、IL 发 ImplMap——**同一 `.cod` 通用** |

- 后端差异全部在**消费端发射时**解决（消费方从合并后的语义程序按后端发独立产物）。
- 系统标准库同理：核心程序集 `System.Core.cod` 从 `src/stdlib/System.Core/` 源码编一次（`requires:any`、纯逻辑、无导入），四路直接消费——"外部文件引用"模型的核心价值（像 .NET 框架参考程序集，发布一份，各处消费）。
- 边界：将来若标准库加 native import 功能层原语，仍是"一个程序集 + 清单平台约束"；跨平台（未来 Linux native）由 manifest 校验拒绝。**真正按后端两份的只有运行期二进制**（native exe vs 托管 dll），`.cod` 永远一份。

## 8. 系统库交付（外部文件，多程序集）
仿 .NET 框架引用模型（✅ 已落地，2026-08-22）：

1. **源码**：`src/stdlib/System.Core/`（`namespace System`，Runtime/Console/Math/String/Array 每类一文件，由 `src/stdlib/System.cosln` 解决方案汇总）。✅
2. **构建**：`tools/build-stdlib.cmd` 用已构建的 `cocoa` 编 `src/stdlib/System.cosln`（内含 `System.Core/System.Core.coproj`，`name=System.Core`）→ `src/stdlib/System.Core/out/System.Core.cod`（检查入库）。✅
3. **部署**：`Cocoa.Core.csproj` 加 `Content`（`CopyToOutputDirectory`）把 `System.Core.cod` 带到 `cocoa.exe`/测试输出目录。✅
4. **加载**：`SystemLibrary.cs`——目录发现 `System*.cod`（`COCOA_STDLIB` env → 单文件向后兼容 / 目录枚举；缺省 `AppContext.BaseDirectory`）；`System.Core.cod` 强制首位；缓存（线程安全）；**缺文件逐文件降级**（坏库跳过、stdlib 不可用但不崩）。✅
5. **注入**：`Compilation` ctor 加载为系统库列表（独立于用户 `_codLibraries`），Binder 命名空间-only 注入 + `BindProgram` 体合并（用户库优先）；用户 `-r` 指向同路径去重。✅
6. **多程序集扩展（6e-M17）**：未来大功能模块（`System.Net.cod`/`System.Json.cod`，仿 C# `System.Net.Http`/`System.Text.Json`）各配 `.coproj` 构建放入目录即自动发现加载，编译器零改动。✅
7. **限制**：`EmitCocoa` 校验——用户 `.cod` 库引用系统库函数 → 明确诊断拒绝（跨 `.cod` 携带依赖留后续）；**各系统模块须自包含**（库体内禁止跨 `.cod` 调用）。✅

> 现状过渡态：`src/stdlib/System.Core/` 各源文件作为**普通源文件**与用户程序一同传给 `cocoa` 编译，三后端一致可用；待第 2~6 步落地后转为隐式注入。

## 10. 与 .NET 交互模型的对照

| .NET 机制 | 我们的对应 |
|-----------|-----------|
| 四层：语言 API → PAL（ConsolePal）→ Interop 声明 → native API | 逻辑层（stdlib）→ 功能层（内置原语）→ 三后端映射 → 运行时/OS API |
| `Interop.Kernel32` 集中导入声明 | `BuiltinFunctions` 规格表 + `IlFramework`/`RuntimeEmitterIR` 后端实现 |
| P/Invoke 编组表（blittable 直通 / bool→BOOL / char→char16 / string→LPWSTR / 数组 pin） | §3 统一 ABI 表；native 侧即"零编组"（`DisableRuntimeMarshalling` 同构） |
| JIT intrinsic（`Math.Sqrt` → `sqrtsd`） | 功能层原语 per-backend 映射（`sqrt` → native SSE/运行时函数） |
| BCL 构建于 Interop + 语言核心之上 | 逻辑层构建于功能层原语 + 语言核心之上 |

**runtime 调用同一批 kernel32 API**：native 运行时 `WriteConsoleW`/`WriteFile`/`ReadConsoleW`/`GetCommandLineW`/`GetStdHandle` 与 .NET `ConsolePal` 一致。

## 11. 治理前置（BuiltinKind）

功能层抽象（stdlib P0，随代码结构治理 Phase 2 落地）：

```csharp
internal enum BuiltinKind { WriteLine, ReadLine, Random, Sleep, TickCount, Exit, Sqrt, Floor, Ceiling, Truncate, Round, Beep }   // + 未来 Pow…

internal sealed record BuiltinSpec(BuiltinKind Kind, string Name, TypeSymbol ReturnType, TypeSymbol[] ParameterTypes);

// 规格表 → 生成 FunctionSymbol（携带 BuiltinKind）+ GetAll/GetByKind/GetByName
```

- `FunctionSymbol` 加 `BuiltinKind?`（非空即内置，作为后端分发稳定 key）。
- 三后端 `switch (node.Function.BuiltinKind)`，替换 `== BuiltinFunctions.X` 引用相等（消除 `.cod` 反序列化按名复用单例的脆弱隐式契约）。
- 收益：新增功能层原语 = 1 行规格 + 3 个 switch case + 1 个 IL 方法引用。

## 12. 决策记录

| 决策 | 结论 |
|------|------|
| 系统库交付 | 外部文件（仿 .NET 引用模型），非内嵌资源 |
| 核心库命名 | 单一核心程序集 `System.Core.cod`（承载 Runtime/Console/Math/String/Array，仿 `System.Private.CoreLib`；6e-M17 由 `System.cod` 改名） |
| 多程序集机制 | 目录发现 `System*.cod`（`System.Core.cod` 强制首位）；未来大模块 `System.Net.cod`/`System.Json.cod` 各配 `.coproj` 构建即自动加载（仿 C# `System.Net.Http`/`System.Text.Json` 独立实现程序集） |
| 函数组织 | 命名空间限定访问（`System.Math.Max` / `using`） |
| double 变体 | **函数重载**（语言支持重载，而非 `MaxD` 式改名） |
| 用户 `.cod` 库 | **全部命名空间-only**（去掉裸注入，破现有 CodLibrary 样例/测试，需更新） |
| `.cod` 版本 | 硬升级 v2（旧库报"需重新编译"，重建样例产物） |
| 逻辑层范围 | Math/String/Array 三模块 |
| 跨 `.cod` 调用 | **不支持**（库体内禁止跨程序集函数调用，各模块自包含；符号调和为独立里程碑） |
