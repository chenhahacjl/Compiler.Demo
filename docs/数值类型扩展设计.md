# 数值类型扩展设计（6e-M21）

> 关联文档：`docs/开发计划.md`、`docs/语法手册.md`
> 最后更新：2026-08-22

---

## 1. 目标

补齐数值类型体系，使语言支持完整的 8/16/32/64 位有/无符号整数与 32/64 位浮点，并在 **CO 方言**中采用 Rust/Zig 风格简写命名（`i8/u8/i16/u16/i32/u32/i64/u64/f32/f64`），与 **C# 方言**原名共存于同一套 `TypeSymbol`（两方言词汇互斥：CO 只认简写、C# 只认原名）。

**范围（已确认）**：
- 完整实现 8/16/32/64 位整数（含无符号）+ `f32`/`f64` 浮点，覆盖绑定/转换/常量折叠/求值器/IL/native 五层与三套测试。
- 无符号语义完整：`u32`/`u64` 的除法、取余用无符号指令，右移用逻辑右移。
- `i128/u128/f128` 先在 CO 词汇占位（识别但报「暂不支持」诊断），实际运算暂缓。
- 整数与浮点一次性铺开（不分先后）。

---

## 2. 类型映射与方言分流

### 2.1 新增 `TypeSymbol`（6 个）+ 占位（3 个）
- 已存在：`Int32`(int)、`Long`(i64/long)、`Byte`(u8/byte)、`Double`(f64/double)。
- 新增：`Int8`(sbyte)、`Int16`(short)、`UInt16`(ushort)、`UInt32`(uint)、`UInt64`(ulong)、`Float32`(float)。
- 占位：`Int128`、`UInt128`、`Float128`。

### 2.2 方言词汇（互斥）
| CO 只认 | C# 只认 | TypeSymbol |
|---|---|---|
| `i8` | `sbyte` | Int8 |
| `u8` | `byte` | Byte |
| `i16` | `short` | Int16 |
| `u16` | `ushort` | UInt16 |
| `i32` | `int` | Int32 |
| `u32` | `uint` | UInt32 |
| `i64` | `long` | Long |
| `u64` | `ulong` | UInt64 |
| `f32` | `float` | Float32 |
| `f64` | `double` | Double |
| `i128`/`u128`/`f128` | — | 占位（报不支持） |

非数值类型 `bool`/`string`/`char`/`void`/`any` 两方言共享，不变。`.cod` 序列化按规范名解析，与源拼写无关。

### 2.3 实现要点
- `Binder` 新增 `_dialect`：由 `BindGlobalScope` 从 `syntaxTrees[0].Dialect` 取得，嵌套 Binder 继承。
- `LookupType(name)` 按方言查两张名字表，映射到同一 `TypeSymbol`。
- 现有 CO 测试/示例源码中用到原名（`int`/`long`/`double`/`byte`、cast `(int)` 等）需机械迁移为简写。

---

## 3. 128 位占位
- `TypeSymbol.Int128/UInt128/Float128`（Name 取 `i128` 等），仅在 CO 名字表注册。
- 用作变量/参数/转换类型时，绑定阶段报诊断「暂不支持 128 位类型」。
- 为将来实装预留扩展点，解析层无需再改。

---

## 4. 数值提升规则 `GetBinaryNumericResultType`
二元运算先求公共计算类型，再按 `(op, 公共类型)` 查表（每种类型只生成一份运算符集）。
- **浮点参与**：任一为 `f32`/`f64` → 更宽浮点（`f64` 优先）；另一操作数隐式提升过去。
- **纯整数**（按位宽/符号无损提升）：
  - 同符号 → 取更宽者（`i16+i32→i32`，`u16+u32→u32`）。
  - 混符号同宽 → 双倍位宽有符号（`i8+u8→i16`，`i16+u16→i32`，`i32+u32→i64`）。
  - 混符号不同宽 → 窄者先按自身符号扩到同宽再套上条。
  - `i64+u64` → 无公共类型 → 报「运算符未定义」。
- **移位**：左操作数按整数提升（小类型升 `i32`），右操作数恒为 `int`（计数掩码：32 位 `0x1F`、64 位 `0x3F`）；结果类型 = 左提升后类型。

> 注：`byte+int` 本方案得 `i64`（无损、数值永不错），C# 得 `int`（可能窄化）。属刻意安全简化。

---

## 5. 转换矩阵（系统化）
将 `Conversion.Classify` 手写 if 链改为按「位宽/有无符号/是否浮点」判定：
- **隐式（拓宽）**：同符号且 `bits(from) ≤ bits(to)`；`unsigned(n) → signed(>n)`（如 `byte→short`、`ushort→int`、`uint→long`）；→ 浮点（`int/long→f32/f64`、`f32→f64`，允许精度损失）。
- **显式（窄化）**：其余数值↔数值组合（含浮点↔整数任意方向除隐式外）。
- 身份/`Any`/字符串/枚举/类继承规则不变。
- 新增 `TypeSymbol` 辅助属性：`IsInteger`、`IsSigned`、`BitWidth`、`IsFloat`，供转换与代码生成统一使用。

## 6. 分阶段实施（每阶段全量测试绿后提交）

- **Phase 0** 类型符号 + 方言分流 `LookupType` + 128 占位诊断 + 字面量后缀 `u/ul/f`（`Lexer.ReadNumber`）+ CO 源码迁移。
- **Phase 1** Binder：转换矩阵系统化 + 二元提升 + 程序化运算符表（11 类型全集，含浮点、有/无符号变体）+ 一元 `~`/`+`/`-`。
- **Phase 2** 常量折叠：按结果类型在 `long/ulong/float/double` 域计算，小类型截断，无符号用 `ulong` 域，移位按位宽掩码。
- **Phase 3** 求值器：整数统一装箱 `long`/`ulong`、浮点 `float`/`double`；数值分支改为按类型取值→计算→归位（新增 `Numeric` helper）。
- **Phase 4** IL：`ToIlType` 补 6 类型；除法/取余/比较按符号选 `Div_Un/Rem_Un`、`Clt_Un/Cgt_Un`；`EmitConversionExpression` 补 `Conv_I1/U1/I2/U2/I4/U4/R4` 及无符号长整型 `Conv_U8`；`f32` 用 `float` 栈。
- **Phase 5** 原生（最重）：按 `(位宽,符号,是否浮点)` 分发；8/16/32 位整数走 32 位路径并透传符号（`>>` 无符号=`Shr` 逻辑、`/` `%`=`Udiv`/`Urem`）；64 位无符号加无符号分支（x64 `xor edx; div`；x86 32 位新增运行时 helper `Udiv64`/`Urem64`）；**f32 真正单精度 SSE**：`X86/X64Assembler` 新增 `Movss/Addss/Subss/Mulss/Divss/Cvtss2sd/Cvtsd2ss/Cvtsi2ss/Cvttss2si/Comiss/Ucomiss/Sqrtss/Roundss`；IR `F*` 运算加单精度变体（或 `single` 标志），load/store 用 4 字节槽 + `movss`。
- **Phase 6** 测试：新增 `Short/Uint/Float` 冒烟（native x64+x86，注意 `\n` vs `\r\n` 约定）、`IlE2eTests` 对应用例、`EvaluationTests` 解释器用例；诊断测试补 `i64+u64` 未定义、`i128` 不支持等。

## 7. 风险
- x86(32 位) u64 除法需新运行时 helper，是原生最花时间处。
- 右移：有符号 `Sar`/无符号 `Shr`，绑定/折叠/求值器/代码生成四处须一致。
- `i64+u64` 编译期报错（128 位暂缓）。
- CO 源码迁移易漏，需 Grep 全量核对 `.co`（含测试与标准库）。
- 每 Phase 保证 29,089 全量测试绿再进下一阶段。
