# Cocoa 互操作手册

> 适用范围：native DLL、.NET DLL、`.cod` 库三类互操作
> 状态：设计中（阶段 6c）
> 最后更新：2026-08-13

---

## 1. 总览

| 目标 | 语法 | 机制 | 平台路径 | 阶段 |
|------|------|------|---------|------|
| native DLL | `import kernel32.dll` | 导入表（运行期加载） | Native + IL | 6 |
| `.cod` 库 | `[references]` / `-r` | 编译期 IR 合并 | Native + IL | 6 |
| .NET DLL | `-r System.Runtime.dll` 等 | AssemblyRef 直通 | 仅 IL | 6 |
| .NET（Native） | — | CLR Hosting | 仅 Native | 9（可选） |

**统一原则**：dll 与 native DLL 的消费统一走 **import 导入表**机制；`.cod` 是编译期机制，与运行期机制分离。

## 2. native DLL 导入

### 2.1 语法

```cocoa
import kernel32.dll

function main()
{
    let h = GetStdHandle(-11)        // 导入表中的函数直接可调
    print("hello")
}
```

coproj 中声明：

```
[imports]
kernel32.dll
user32.dll
```

### 2.2 机制

1. 解析 DLL 导出表（现有 `PeExportTable` 读侧）→ 符号名 → 序数/地址
2. 生成导入描述符 + IAT（现有 `.idata` 基础设施复用）
3. `import` 的名字解析到 IAT 槽；运行时加载器填充地址
4. 未知符号 → 诊断错误（可配置：警告 + 运行时失败）

### 2.3 调用约定（Native）

| 平台 | 约定 | 说明 |
|------|------|------|
| x86 | `cdecl`（默认）/ `stdcall` | 导入函数声明可标注 |
| x64 | 单一约定（Windows x64 统一） | 无需标注 |

```cocoa
import user32.dll
cdecl function MessageBoxA(hWnd: int, text: int, caption: int, type: int): int
```

### 2.4 与 `export` 的关系

- 本编译器 `-f dll` 导出（`export fn`）→ 其他 Cocoa 程序/其他语言程序 `import` 消费
- 同一导入表机制，双向闭环

## 3. `.cod` 库引用

```cocoa
// lib.cod 由 coc build -p lib.coproj -f cod 生成
// 消费方 coproj:
[references]
../Libs/lib.cod
```

- 加载 `.cod` → 反序列化 IR → 符号表并入编译单元 → 引用解析
- 符号冲突检测（同名导出 → 错误）
- 平台不匹配 → 错误（`cod` 头含平台信息）

### 3.1 依赖传递

`.cod` 头部含**依赖清单**（.NET 程序集引用 + native 导入列表，见 `docs/项目格式规范.md` §4.1）。消费方加载 `.cod` 时：

1. 反序列化 IR 与符号表
2. 读取依赖清单
3. .NET 程序集引用 → 并入消费方引用集（IL 路径 AssemblyRef）
4. native 导入 → 合并 `import` 声明（→ 导入表）
5. 被引用的 `.cod` → 递归加载

### 3.2 与 .NET 混用

导入 `.cod` 可以编译成 .NET 程序（IL 路径），因为 IR 支持 `.NET 元数据`外部符号（`docs/IR设计.md` §2.1），cod 代码与 .NET 程序集引用在同一次编译中并存：

```
foo.cod（IR，内部可引用 .NET API）
    │ [references] 加载 + 依赖传递
    ▼
消费方编译单元 ──► IL 后端 ──► 托管 PE（.NET 程序）
```

| 消费方产物 | 结果 |
|-----------|------|
| `-f exe`（IL 路径） | .NET 托管程序（`dotnet x.exe` 运行） |
| `-f dll`（IL 路径） | .NET 库，可被其他 .NET 程序引用 |
| `-f exe`（Native，纯 Cocoa 代码） | 原生 PE |
| Native + cod 含 .NET 调用 | 阶段 9 CLR Hosting |

**边界**：Cocoa 泛型是编译期特化，cod 中已特化的泛型可引用 .NET 泛型类型；.NET 运行期泛型元数据无法反向进入 IR。

## 4. .NET DLL 导入（IL 路径）

```cocoa
// 编译：coc main.co -r System.Runtime.dll
System.Console.WriteLine("hello")
System.Math.Max(10, 20)
```

### 4.1 机制

- IL 路径：`AssemblyRef` 直通（阶段 5 自研元数据写入器支持 AssemblyRef 表）
- 类型映射：`System.Xxx` → 元数据引用；Cocoa 基础类型映射到 CLR 类型
- 解析与重载：当前 Mono.Cecil 的 MetadataResolver 在阶段 5 重写为自研元数据读取

### 4.2 边界（阶段 6 范围）

| 能力 | 状态 |
|------|------|
| 静态方法调用 `call` | 阶段 6 |
| 实例方法调用 `callvirt` / 属性访问 | 阶段 6（语言扩展后） |
| 对象创建 `newobj` | 阶段 6（record/类支持后） |
| 泛型类型 | 阶段 6 |
| 异常 try/catch | 阶段 6 |

### 4.3 Native 路径的 .NET 互操作（阶段 9 可选）

- 通过 CLR Hosting API（`ICLRRuntimeHost` 等）在 Native 进程内加载 .NET 运行时并调用
- 纯 Windows 原生互操作，无第三方依赖
- 前置：阶段 6 的 native DLL 导入（Hosting API 本身就是 native API）
