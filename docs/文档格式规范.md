# Cocoa 文档格式规范

> 状态：✅ 生效（2026-09-06，全仓库 .md 统一约定）
> 定位：本仓库所有 Markdown 文档的统一写作规范，指定 **docs/ 与 docs-dev/ 的层次约定、头部模板、状态标记、链接写法与维护纪律**。
> 相关：[docs/README.md](README.md)（文档索引）、[`docs-dev/README.md`](../docs-dev/README.md)（分类约定）、[库卫生](./项目格式规范.md)

---

## 1. 分层约定

| 目录 | 内容 | 维护方 |
|------|------|--------|
| `docs/` | 正式参考——面向用户的当前真实状态文档（含 `📋` 未实现规划项标注，但**不允许「已实现却说设计中」的陈旧状态**） | 每次特性落地同步 |
| `docs-dev/` | 开发文档——内部规划 / 执行记录 / 设计依据。已实现特性的设计依据移入 `archive/`，未开工规划放 `plan/` | 随里程碑维护 |
| 根 `README.md` / `CODING.md` / `CHANGELOG.md` | 仓库入口 / 开发规范 / 变更日志 | 随变更维护 |

`plan/`（规划·待办）：`自举缺口分析`、`语义债务清单`、`重构执行计划`、`Cocoa.IDE设计`、`UI库规划`、`IR分层与格式设计`
`archive/`（已实现·设计依据保留）：`对象模型设计`、`OOP设计`、`out与ref参数设计`、`内部调用与互操作设计`、`数值类型扩展设计`、`委托与Lambda设计`、`泛型设计`、`类库设计`、`标准库设计`、`SDK标准库增强方案`、`输出格式`、`文档注释设计`、`代码结构`

## 2. 头部块模板

除 `< 100` 行的简单索引/清单外，每个 `.md` 头部统一为：

```markdown
# <文档标题>

> 状态：<emoji> <状态词>（<最近更新日期>）
> 定位：一句话描述本文档用途
> 相关：[<短名>](<相对路径.md>)…

---

<正文>
```

- `> 定位` 必须一句话讲清"谁、在什么场景、来这里找什么"。
- `> 相关` 列出直接相关的其他文档（最多 4 个），缺失可省略该行。

## 3. 状态标记词表

每份文档头部唯一状态行，正文内的进度项沿用同一词表：

| emoji | 含义 | 适用 |
|-------|------|------|
| ✅ | 已实现 / 已落地 / 已生效 | docs 正文及状态行 |
| 🔧 | 实施中 / 设计中 / 进行中 | 规划中的当前工作 |
| 📋 | 定稿未开工 / 规划待办 | 已拍板未动的方案 |
| 🧭 | 方向性规划（未定稿） | plan/ 内文档 |
| 🛑 | 已废弃 / 已归档（仅作历史） | archive/ 内文档 |

**纪律**：特性落地当天翻转对应 ✅，禁止让"已实现"内容停留在 🔧/📋。这是本仓库此前"文档陈旧"问题的根治点。

## 4. 标题层级

- 每个 `.md` 顶部至多一个 `#`；正文不可再现 `#`。
- `docs/` 手册保留 `## N. 节名` 编号（如 `## 12. 类与面向对象`）；`docs-dev/` 设计稿 `##` 不加编号。
- `###` 仅用于节内小节；全仓库禁用四级及以上标题（改文字加粗）。

## 5. 链接写法

- 一律相对路径 + 显示短名：`[语法手册](语法手册.md)`、[`docs-dev/开发计划`](../docs-dev/开发计划.md)。
- 链接目标必须真实存在；**不得把 docs-dev 文件写成 `docs/` 前缀**（历史 83 处错链即此误），反之亦然。
- 归档文件内部旧链接失效时改指 `archive/` 当前路径或新版权威文档。

## 6. 长度与目录

- 正文 > 1500 行强制含 `## 目录` TOC；800–1500 行建议含。
- 单节过长时优先拆子节 `###`，不物理拆文件（语法手册 2837 行单文件原则）。

## 7. 仓库卫生（全程强制）

- UTF-8 无 BOM；工作区 CRLF（`*.sh` LF）；禁混合换行（`git ls-files --eol` 抽查 mixed=0）。
- 无尾随空格；diff 中不得出现整文件重归一化。
- 交叉引用一律真实路径；提交 message 前缀分类：`docs(fmt)` / `docs(org)` / `docs(merge)` / `docs(fix)` / `docs(new)` / `docs(manual)`。
