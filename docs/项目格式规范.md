# Cocoa 项目格式规范

> 适用范围：`.coproj`（项目文件）、`.cosln`（解决方案文件）、`.cod`（Cocoa 库文件）、增量构建缓存
> 状态：✅ 已落地（阶段 6d-1，2026-08-18；`.cod` 库格式与依赖清单仍属后续章节）
> 最后更新：2026-08-18

---

## 1. 设计原则

- **轻量文本**：不用 JSON/XML，行式 `key = value` + 分节，可手写、可 diff
- **注释友好**：`#` 行注释
- **确定性**：相同输入 → 相同输出
- **相对路径**：所有路径相对文件自身所在目录

> **6d-1 实现状态**：`.coproj` / `.cosln` 解析、glob 展开、增量缓存、`.coproj.user` 用户覆盖、
> 项目/解决方案构建、`coc build` CLI 均已落地。
> **6d-2 补充**：`entry` 字段已接线——入口函数名默认 `main`，可改为任意函数（带参入口须为
> `function xxx(args: string[])`，`args` 为命令行参数组；详见 `docs/编译手册.md`）。
> 以下仍为占位/待接线：`output = dll / cod` 发射（构建报"not implemented yet"）、`[references]` 中的 `.cod` 库
> （构建报错）、`[imports]` 节（构建仅警告）。
> 参考实现：`src/Cocoa/Projects/`；样例：`samples/DemoSolution/`。

## 2. `.coproj` 项目文件

### 2.1 文件结构

```
# 注释：项目名与基本属性
name = MyApp
output = exe            # exe | dll | cod
platform = x64          # x86 | x64（Native 输出有效）
entry = main            # 入口函数名，仅 output = exe 有效

[sources]
src/*.co
src/**/*.co

[references]
lib.cod
../Libs/MyLib.cod

[imports]
kernel32.dll
user32.dll

[options]
incremental = true      # 增量构建开关（默认 true）
debug = true            # 调试模式（默认 false）
outputPath = bin
```

### 2.2 节与字段

| 节 | 字段 | 必填 | 默认值 | 说明 |
|----|------|------|--------|------|
| 顶层 | `name` | 否 | 文件名（不含扩展名） | 项目名，默认输出名 |
| 顶层 | `output` | 否 | `exe` | 输出格式：`exe` / `dll` / `cod` |
| 顶层 | `platform` | 否 | `x64` | Native 目标平台：`x86` / `x64` |
| 顶层 | `entry` | 否 | `main` | 入口函数名（仅 `output = exe`） |
| `[sources]` | — | 是 | — | 源文件 glob 模式，每行一个 |
| `[references]` | — | 否 | — | 引用库路径（`.cod`，Native/IL 均可） |
| `[imports]` | — | 否 | — | native DLL 名列表（→ 导入表） |
| `[options]` | `incremental` | 否 | `true` | 增量构建 |
| `[options]` | `debug` | 否 | `false` | 调试模式 |
| `[options]` | `outputPath` | 否 | `.` | 输出目录（相对项目文件目录） |

### 2.3 解析规则

- 行格式：`key = value`，`=` 两侧空白忽略；空行忽略
- 以 `[` 开头的行进入新节；节外的字段属于顶层
- 顶层未知字段忽略（允许扩展）；节内条目均为值列表
- glob 模式至少匹配一个文件，否则警告
- `output` / `platform` 非法值 → `ProjectFileFormatException`

### 2.4 glob 模式

| 模式 | 匹配 |
|------|------|
| `*.co` | 当前目录所有 `.co` |
| `src/**/*.co` | `src/` 及其子目录递归 |
| `src/*.co` | `src/` 下一层 |
| `main.co` | 单文件精确匹配 |

## 3. `.cosln` 解决方案文件

```
name = MyApp

[projects]
src/Core/Core.coproj
src/App/App.coproj

# 可选的配置覆盖（后续扩展）
[projectConfig]
src/App/App.coproj = build:true
```

| 节 | 字段 | 必填 | 说明 |
|----|------|------|------|
| 顶层 | `name` | 否 | 解决方案名 |
| `[projects]` | — | 是 | 项目文件相对路径，每行一个 |
| `[projectConfig]` | — | 否 | `路径 = build:true/false` 按项目覆盖 |

**编译顺序**：由 `[references]` 中的 `.cod` 项目引用关系拓扑排序（先编译被引用者）；无依赖时按声明顺序。检测到循环依赖报错。

## 3.1 `.coproj.user` 用户级配置（IDE 预留）

> 仿 `.csproj.user`：同一目录下 `<项目文件名>.coproj.user`，**仅存在于本地、gitignored 不入库**，保存个人/机器相关覆盖。`CocoaProjectFile.Load` 检测到存在时按同一轻量格式解析并合并。

### 3.1.1 可覆盖的键（构建专属）

| 层 | 键 |
|----|-----|
| 顶层 | `name` / `output` / `platform` / `entry` |
| `[options]` | `incremental` / `debug` / `outputPath` |

### 3.1.2 优先级

```
.coproj 基础值  <  .coproj.user 覆盖  <  命令行参数（-f/--platform/-o/--debug/--release/--no-incremental）
```

### 3.1.3 IDEA 预留契约

- `[sources]` / `[references]` / `[imports]` 节在 `.user` 中**不生效**（项目形状由共享文件决定）
- **未知节（如 `[ide]`）与未知顶层键一律忽略不报错**：IDE 可自行追加任意节保存启动对象、窗口状态等，构建工具不受影响
- 已知键的非法值仍报 `ProjectFileFormatException`（含行号），与 `.coproj` 一致
- `.cosln.user`（解决方案级用户配置）列为后续预留

## 4. `.cod` 库文件格式

`.cod` 是 Cocoa 编译的库文件（阶段 1 的 IR 序列化）：

| 部分 | 内容 |
|------|------|
| 头 | 魔数 `COCOD` + 版本 + 目标平台 |
| 依赖清单（manifest） | 引用的 .NET 程序集列表 + `import` 的 native DLL 列表 |
| 符号表 | 导出的函数/类型符号（名称 → IR 位置） |
| 代码区 | IR 序列化（与阶段 1 的 IR 文本/二进制格式一致） |

- `.cod` 通过 `[references]` 引用，编译器加载后合并编译
- 与 `-f dll`（native 导出库）互斥：`cod` 是编译期合并，`dll` 是运行期导入
- 阶段 6c 落地；格式细节随 IR 层定稿（见 `docs/IR设计.md`）

### 4.1 依赖清单（manifest）

`.cod` 中的代码可能引用外部符号（见 `docs/IR设计.md` §2），因此头部必须声明依赖，消费方编译器加载 `.cod` 时自动传递：

| 依赖类型 | 声明内容 | 消费方行为 |
|---------|---------|-----------|
| .NET 程序集 | 程序集名 + 版本（等价 AssemblyRef 清单） | 加入消费方引用集（IL 路径 → AssemblyRef 表） |
| native DLL | DLL 名列表 | 合并 `import` 声明（→ 导入表） |
| `.cod` 库 | 被引用的 `.cod` 路径/标识 | 递归加载 |

- 缺清单的 `.cod`（纯 Cocoa 基础类型代码）不要求此节
- 依赖冲突（版本不同）→ 错误或按消费方优先规则（定稿时确定）

### 4.2 与 .NET 组合能力

| 消费方产物 | 导入 `.cod` | 结果 |
|-----------|------------|------|
| `-f exe`（IL 路径） | ✅ | .NET 托管程序（`dotnet x.exe` 运行），cod 依赖的 .NET 程序集经依赖清单传递 |
| `-f dll`（IL 路径） | ✅ | .NET 库，可被其他 .NET 程序引用 |
| `-f exe` / `-f dll`（Native） | ✅（纯 Cocoa 代码） | 原生 PE |
| Native + cod 含 .NET 调用 | ⏳ 阶段 9 | 需 CLR Hosting |

## 5. 增量构建

### 5.1 缓存

缓存**集中**存放于解决方案/项目根的隐藏状态目录 `.coc/`（仿 C# 的 `.vs/`，后续 IDE 状态也放这里）：

| 构建入口 | 缓存位置 |
|----------|---------|
| `.cosln` | `<解决方案目录>/.coc/<项目相对路径>/<name>.cache`（按相对目录分层，避免同名冲突） |
| `.coproj`（单项目） | `<项目目录>/.coc/<name>.cache` |
| 项目位于作用域外 | `.coc/<项目文件夹名>/<name>.cache`（越界回退，仍不逃出 `.coc/`） |

缓存文件内容：每个源文件的哈希（SHA-256） + glob 展开结果 + 引用文件元数据 + imports + 构建选项快照。
命中判定：哈希相同 + 选项相同 + 依赖 `.cod` 未变化。

### 5.2 行为

- `incremental = true`（默认）：全部命中 → 跳过编译（输出 "up to date"）；部分变化 → 仅重编变化项目
- 源文件/引用/选项任一变化 → 重新编译该文件或整个项目（先按文件粒度，文件级失效规则阶段 6 定稿）
- 缓存目录可删除，删除后全量重建

## 6. 错误与诊断

| 场景 | 处理 |
|------|------|
| 文件不存在 | `FileNotFoundException` |
| 格式非法 | `ProjectFileFormatException`（含行号） |
| `[projects]` 缺失（cosln） | `ProjectFileFormatException` |
| glob 未匹配 | 警告 |
| 循环依赖 | 错误 + 环路径 |
| `.cod` 平台不匹配 | 错误 |
