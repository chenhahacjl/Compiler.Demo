# Cocoa 项目格式规范

> 适用范围：`.coproj`（项目文件）、`.cosln`（解决方案文件）、`.cod`（Cocoa 程序集）、增量构建缓存
> 状态：✅ 已落地（阶段 6d-1，2026-08-18；`.cod` 程序集格式与依赖清单属阶段 6b，设计中）
> 最后更新：2026-08-20（entry 限定名 `ClassName.Method` / `Namespace.ClassName.Method`；`.cod` 定位为 Cocoa 程序集）

---

## 1. 设计原则

- **轻量文本**：不用 JSON/XML，行式 `key = value` + 分节，可手写、可 diff
- **注释友好**：`#` 行注释
- **确定性**：相同输入 → 相同输出
- **相对路径**：所有路径相对文件自身所在目录

> **6d-1 实现状态**：`.coproj` / `.cosln` 解析、glob 展开、增量缓存、`.coproj.user` 用户覆盖、
> 项目/解决方案构建、`cocoa build` CLI 均已落地。
> **6d-2 补充**：`entry` 字段已接线——入口函数名默认 `Main`，可改为任意函数（带参入口须为
> `function xxx(args: string[])`，`args` 为命令行参数组；详见 `docs/编译手册.md`）。
> **6e-M11 补充**：`entry` 支持**限定名**——`ClassName.Method` 或 `Namespace.ClassName.Method`
> （类静态方法入口，命名空间全名可选），默认仍为顶层/类 `Main`；`using Foo.Bar;` 分号可省略。
> **M3 补充**：`output = library`（.NET 托管 dll）已实现，供 `-r` + `using` 消费（`docs-dev/类库设计.md`）。
> **三格式分工**：`output = executable`（可执行）/ `library`（.NET dll，跨语言桥）/ `cocoa`（`.cod` Cocoa 程序集，语义层 BoundProgram 编译期合并，native/IL 通用，阶段 6b）。
> 以下仍为占位/待接线：`output = cocoa`（`.cod` 发射，构建报"not implemented yet"）、`.cod` 引用加载、`[imports]` 节（构建仅警告）。
> 参考实现：`src/Cocoa.Core/Projects/`；样例：`samples/Tutorial/`、`samples/Libraries/NetLibrary/`、`samples/Libraries/CodLibrary/`。

## 2. `.coproj` 项目文件

### 2.1 文件结构

```
# 注释：项目名与基本属性
name = MyApp
output = executable      # executable | library | cocoa
platform = x64          # x86 | x64（Native 输出有效）
entry = main            # 入口：顶层函数名 / ClassName.Method / Namespace.ClassName.Method（默认 Main）
dotnetRuntime = net48  # net40 | net48 | net8.0 | net9.0（仅 dotnet 后端）

[sources]
src/*.co
src/**/*.co

[references]
../Libs/MyLib.coproj   # 项目引用：自动构建 + 产物复制到当前项目生成目录（仅 cocoa/library 可被引用）
lib.cod                # Cocoa 程序集（预编译产物，阶段 6b）
mylib.dll              # .NET 程序集（跨语言桥）

[imports]
kernel32.dll
user32.dll

[options]
incremental = true      # 增量构建开关（默认 true）
debug = true            # 调试模式（默认 false）
outputPath = bin
```

### 2.2 节与字段

| 节 | 字段 | 必填 | 默认值 | 说明 |
|----|------|------|--------|------|
| 顶层 | `name` | 否 | 文件名（不含扩展名） | 项目名，默认输出名 |
| 顶层 | `output` | 否 | `executable` | 输出格式：`executable` / `library` / `cocoa` |
| 顶层 | `platform` | 否 | `x64` | Native 目标平台：`x86` / `x64` |
| 顶层 | `entry` | 否 | `Main` | 入口函数：顶层函数名，或 `ClassName.Method` / `Namespace.ClassName.Method`（类静态方法；仅 `output = executable`；`cocoa`/`library` 无入口） |
| 顶层 | `dotnetRuntime` | 否 | `net48` | .NET 目标框架 TFM（仅 dotnet 后端）：`net40` / `net48` / `net8.0` / `net9.0` |
| `[sources]` | — | 是 | — | 源文件 glob 模式，每行一个 |
| `[references]` | — | 否 | — | 引用列表（每行一个）：`.coproj` 项目引用（自动递归构建 + 产物复制到当前项目生成目录）/ `.cod` Cocoa 程序集 / `.dll` .NET 程序集，供 `using` 消费；`-r` 同 |
| `[imports]` | — | 否 | — | native DLL 名列表（→ 导入表） |
| `[options]` | `incremental` | 否 | `true` | 增量构建 |
| `[options]` | `debug` | 否 | `false` | 调试模式 |
| `[options]` | `outputPath` | 否 | `.` | 输出目录（相对项目文件目录） |

### 2.3 解析规则

- 行格式：`key = value`，`=` 两侧空白忽略；空行忽略
- 以 `[` 开头的行进入新节；节外的字段属于顶层
- 顶层未知字段忽略（允许扩展）；节内条目均为值列表
- glob 模式至少匹配一个文件，否则警告
- `output` / `platform` 非法值 → `ProjectFileFormatException`

### 2.5 项目引用（`[references]` 中的 `.coproj`）

引用 `.coproj` = 项目引用（类 C# `<ProjectReference>`），每个 coproj 是一个独立文件单元：

1. **加载并校验**被引用项目：`output` 必须为 `cocoa` 或 `library`（`executable` → 错误"不能引用可执行项目"）
2. **自动递归构建**被引用项目（其 `output`/`entry`/`references` 用自己配置；`backend`/`dotnetRuntime`/`debug`/`platform`/`cacheRoot` 继承当前构建环境）；循环引用 → 错误 + 环路径
3. **产物自动复制到当前项目的生成目录**（`GetOutputDirectory()`）：`cocoa` → `.cod`（阶段 6b 消费合并）/ `library` → `.dll`（运行期部署，CLR 探测当前目录即可加载）
4. 消费者以复制后的产物路径参与编译（`.cod` 语义层合并 / `.dll` 元数据引用）
5. CLI `-r` 同语义（`-r ../Libs/MyLib.coproj`）

### 2.4 glob 模式

| 模式 | 匹配 |
|------|------|
| `*.co` | 当前目录所有 `.co` |
| `src/**/*.co` | `src/` 及其子目录递归 |
| `src/*.co` | `src/` 下一层 |
| `main.co` | 单文件精确匹配 |

## 3. `.cosln` 解决方案文件

```
name = MyApp

[projects]
src/Core/Core.coproj
src/App/App.coproj

# 可选的配置覆盖（后续扩展）
[projectConfig]
src/App/App.coproj = build:true
```

| 节 | 字段 | 必填 | 说明 |
|----|------|------|------|
| 顶层 | `name` | 否 | 解决方案名 |
| `[projects]` | — | 是 | 项目文件相对路径，每行一个 |
| `[projectConfig]` | — | 否 | `路径 = build:true/false` 按项目覆盖 |

**编译顺序**：由 `[references]` 中的项目引用关系拓扑排序（先编译被引用者）；无依赖时按声明顺序。检测到循环依赖报错。依赖边匹配 `[references]` 中的 `.coproj` 路径（解析后全路径比较，直接命中项目文件）与 `.cod`/`.dll` 产物路径。`.cod` 项目（`output = cocoa`）无入口；`library`/`executable` 项目不参与依赖图。

## 3.1 `.coproj.user` 用户级配置（IDE 预留）

> 仿 `.csproj.user`：同一目录下 `<项目文件名>.coproj.user`，**仅存在于本地、gitignored 不入库**，保存个人/机器相关覆盖。`CocoaProjectFile.Load` 检测到存在时按同一轻量格式解析并合并。

### 3.1.1 可覆盖的键（构建专属）

| 层 | 键 |
|----|-----|
| 顶层 | `name` / `output` / `platform` / `entry` |
| `[options]` | `incremental` / `debug` / `outputPath` |

### 3.1.2 优先级

```
.coproj 基础值  <  .coproj.user 覆盖  <  命令行参数（-f/--platform/-o/--debug/--release/--no-incremental）
```

### 3.1.3 IDEA 预留契约

- `[sources]` / `[references]` / `[imports]` 节在 `.user` 中**不生效**（项目形状由共享文件决定）
- **未知节（如 `[ide]`）与未知顶层键一律忽略不报错**：IDE 可自行追加任意节保存启动对象、窗口状态等，构建工具不受影响
- 已知键的非法值仍报 `ProjectFileFormatException`（含行号），与 `.coproj` 一致
- `.cosln.user`（解决方案级用户配置）列为后续预留

## 4. `.cod` 程序集格式

`.cod` 是 Cocoa 的**程序集**分发格式（等价 .NET dll 语义）：每库一个/多个 `namespace`、**无入口点**、公共符号表按命名空间组织。**内容为语义层 `BoundProgram`（降级绑定树 + 符号表）序列化**（阶段 6b），而非 native 三地址码 IR——只有语义层才能被 native（`BoundTreeToIr`）与 IL（`IlEmitter`）双后端通用，对应 .NET 的 IL 程序集概念：

| 部分 | 内容 |
|------|------|
| 头 | 魔数 `COCOD` + 版本 + 平台要求 + **backend 要求（`requires`）** |
| 依赖清单（manifest） | 引用的 .NET 程序集列表 + `import` 的 native DLL 列表 + 被引用的 `.cod` 列表 |
| 公共符号表 | 导出的 public 类型/函数/枚举/全局变量（按命名空间组织） |
| 代码区 | 序列化 `BoundProgram`（函数体 + 类成员，后端无关）+ 私有依赖闭包（公共符号传递引用的私有函数/类型/字符串/常量） |

- `.cod` 由 `output = cocoa` 项目产出（编译到 BoundProgram 即停，不走 IR/机器码/IL）；通过 `[references]` / `-r` 引用，编译器加载后**合并编译**，消费方按自己的后端/平台产出独立 dll/exe
- **无入口点**：`output = cocoa` 源码须含 `namespace`，禁止 `Main`/入口（违者编译报错）
- **backend 要求推导**（`-f cocoa` 发射时扫描库内容）：含 .NET API 或 OOP（class 实例化/继承；主程序内用户类 native 已规划 6e-M19，`.cod` 库 OOP 仍 `requires: dotnet`）→ `requires: dotnet`；含 native import → 绑定平台、双后端可用；纯函数 + 基础类型 → `requires: any`（双后端通用）
- 消费方后端与 `requires` 不匹配 → **编译期报错**（如 native 消费 `requires: dotnet`）
- 与 `-f dll`（native 导出库）互斥：`cocoa` 是编译期合并，`dll` 是运行期导入
- 平台无关：纯 Cocoa 代码跨平台；含 native import 时绑定平台（消费方平台不匹配报错）
- 阶段 6b 落地；格式细节见 `docs-dev/IR设计.md` §7
- **格式版本 v2（6e-M14）**：`fn` 符号增 `ns`（函数命名空间）字段；读侧校验版本，旧库报"需重新编译"；消费改为命名空间-only 注入（`using MyLib;` 或 `MyLib.Func(...)`）。见 `docs-dev/标准库设计.md` §6/§7
- **中间库性质**：`.cod` 一次编译、多端消费，不按后端/平台区分；`requires`/平台是消费端校验门，后端差异在消费端发射时解决

### 4.1 依赖清单（manifest）

`.cod` 头部声明依赖与约束，消费方编译器加载 `.cod` 时自动传递：

| 依赖类型 | 声明内容 | 消费方行为 |
|---------|---------|-----------|
| backend 要求 | `requires: dotnet` / `native` / `any`（+ 平台） | 消费方后端/平台不匹配 → 编译期报错 |
| .NET 程序集 | 程序集名 + 版本（等价 AssemblyRef 清单） | 加入消费方引用集（IL 路径 → AssemblyRef 表） |
| native DLL | DLL 名列表 | 合并 `import` 声明（→ 导入表） |
| `.cod` 程序集 | 被引用的 `.cod` 路径/标识 | **递归加载**（防环 + 去重，同一 `.cod` 只加载一次） |

- 缺清单的 `.cod`（纯 Cocoa 基础类型代码）不要求此节，`requires` 默认 `any`
- 依赖冲突（版本不同）→ 错误或按消费方优先规则（定稿时确定）
- 增量缓存须按**传递**依赖哈希失效（A→B→C，C 变则 A 失效）

### 4.2 与 .NET 组合能力

| 消费方产物 | 导入 `.cod` | 结果 |
|-----------|------------|------|
| `-f exe`（IL 路径，netcore） | ✅ | .NET 托管程序（原生 apphost `x.exe` 直接运行 / `dotnet x.dll`），cod 依赖的 .NET 程序集经依赖清单传递 |
| `-f exe`（IL 路径，netfx `--dotnet-runtime net4x`） | ✅ | .NET Framework 托管程序（Windows 直接运行 `x.exe`，无需 dotnet 前缀） |
| `-f dll`（IL 路径） | ✅ | .NET 库，可被其他 .NET 程序引用 |
| `-f exe` / `-f dll`（Native，`requires: any` 或含 native import） | ✅ | 原生 PE |
| Native + cod 含 .NET 调用（`requires: dotnet`） | ❌ 编译期报错 | 需阶段 9 CLR Hosting |

## 5. 增量构建

### 5.1 缓存

缓存**集中**存放于解决方案/项目根的隐藏状态目录 `.cocoa/`（仿 C# 的 `.vs/`，后续 IDE 状态也放这里）：

| 构建入口 | 缓存位置 |
|----------|---------|
| `.cosln` | `<解决方案目录>/.cocoa/<项目相对路径>/<name>.cache`（按相对目录分层，避免同名冲突） |
| `.coproj`（单项目） | `<项目目录>/.cocoa/<name>.cache` |
| 项目位于作用域外 | `.cocoa/<项目文件夹名>/<name>.cache`（越界回退，仍不逃出 `.cocoa/`） |

缓存文件内容：每个源文件的哈希（SHA-256） + glob 展开结果 + 引用文件元数据 + imports + 构建选项快照。
命中判定：哈希相同 + 选项相同 + 依赖 `.cod` 未变化。

### 5.2 行为

- `incremental = true`（默认）：全部命中 → 跳过编译（输出 "up to date"）；部分变化 → 仅重编变化项目
- 源文件/引用/选项任一变化 → 重新编译该文件或整个项目（先按文件粒度，文件级失效规则阶段 6 定稿）
- 缓存目录可删除，删除后全量重建

## 6. 错误与诊断

| 场景 | 处理 |
|------|------|
| 文件不存在 | `FileNotFoundException` |
| 格式非法 | `ProjectFileFormatException`（含行号） |
| `[projects]` 缺失（cosln） | `ProjectFileFormatException` |
| glob 未匹配 | 警告 |
| 循环依赖 | 错误 + 环路径 |
| `.cod` 平台不匹配 | 错误 |
| `.cod` backend 不匹配（native 消费 `requires: dotnet`） | 错误（编译期） |
| `output = cocoa` 含入口 / 缺 namespace | 错误（阶段 6b） |
| 引用 `executable` 项目 | 错误（仅 `cocoa`/`library` 可被引用） |
| `.coproj` 循环引用 | 错误 + 环路径 |
| 引用文件类型未知（非 `.coproj`/`.cod`/`.dll`） | 错误 |
