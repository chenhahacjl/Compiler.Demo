# Cocoa 内部调用与互操作设计（syscall / import 块 / extern 元数据）

> 状态：🔧 设计中（2026-08-22）
> 范围：本次会话全部设计决策。实施按 `docs/开发计划.md` 6e-M17 里程碑分步落地，每步独立验证、更新文档、提交 git。
> 相关文档：`docs/标准库设计.md`（分层模型）、`docs/互操作手册.md`（native DLL 导入）、`docs/语法手册.md` §36（模块与导入导出）

---

## 1. 设计动机

现状三个痛点：

1. **内置原语是隐式魔法符号**：`print`/`input`/`random` 由 `BuiltinFunctions` 规格表硬编码 + `CreateRootScope` 隐式注入全局作用域（`Binder.cs:1536`），无法在源码中声明、无法在系统库中显式依赖。
2. **import 归属靠位置**：`import kernel32.dll` 后跟 extern 函数，DLL 与函数的关系只有"位置"，混排时看不出哪个函数属哪个 DLL。
3. **extern 缺失 C# `[DllImport]` 能力面**：只有 DLL 名 + 调用约定，缺入口别名、缺编码格式（CharSet）。

**总目标**：把内置原语演进为**可声明的内部调用核心库**（仿 .NET `System.Private.CoreLib` + `[MethodImpl(InternalCall)]`），把 extern 演进为**强制类内 + 声明式归属 + 完整互操作元数据**（仿 C# `[DllImport]`）。

## 2. 架构定位：三层系统库

.NET 对照：`System.Private.CoreLib`（内部调用声明层）+ facade 程序集（类型转发）+ BCL 逻辑层。

Cocoa 简化后（无多程序集/无 type-forwarding/无跨 `.cod` 引用）：

```
System.Core.cod（核心程序集，编译自 System.co，目录发现自动加载）
├── class System.Runtime { syscall function ... }            ← 内部调用层（syscall 声明）
├── namespace System.Console { function WriteLine(...) { Runtime.Print(...) } }  ← 封装层（用户 API）
└── namespace System.Math / System.String / System.Array                ← 逻辑层（现有，不变）
```

**关键决策（6e-M17 修订）**：**单一核心程序集** `System.Core.cod`（承载全部核心库内容，仿 .NET `System.Private.CoreLib`）——不按 Math/String/Array 拆实现程序集（C# 亦不拆，见 `标准库设计.md §8`）。为未来"多分类"提供**目录发现机制**：`SystemLibrary` 枚举 `System*.cod`（`System.Core.cod` 强制首位），大功能模块（`System.Net.cod`/`System.Json.cod`，仿 C# `System.Net.Http`/`System.Text.Json`）各配 `.coproj` 构建放入目录即自动加载，编译器零改动。约束：**各模块须自包含**（库体内禁止跨 `.cod` 调用；跨库符号调和为独立里程碑）。

## 3. 语言特性一：`syscall function`（内部调用声明）

### 3.1 语法

```cocoa
// System.co 内
namespace System
{
    class Runtime                          // 完整名 System.Runtime（命名空间 System + 类 Runtime）
    {
        syscall function Print(text: string): void     // 无函数体
        syscall function Input(): string
        syscall function Random(max: int): int
        syscall function Sleep(ms: int): void
        syscall function Now(): int
        syscall function Exit(code: int): void
    }
}
```

### 3.2 规则

| 项 | 规则 |
|---|---|
| 关键字 | `syscall` 新修饰符（与 `cdecl`/`stdcall` 同类，`ParseModifiers` 收集） |
| 声明位置 | 类内方法（与 extern 进类一致）；`System.Runtime`（命名空间 System + 类 Runtime） |
| 函数体 | 禁止（有函数体 → 诊断错误） |
| 名称解析 | 声明名必须命中 `BuiltinFunctions` 内置表 → **复用同一 singleton**（带 `BuiltinKind`） |
| 规范名 | **C# 风格 PascalCase**（`Print`/`Input`/`Random`/`Sleep`/`Now`/`Exit`，6e-M17 Step 2）；旧小写裸调用 `print(...)` 回退命中已于 **Step 3 迁移后移除** |
| 未命中 | 诊断错误（不是普通函数） |
| 后端分发 | **零改动**——复用 `BuiltinKind` 三后端 switch（Evaluator/IL/native） |

### 3.3 与 extern 的分工

| | `extern`（import DLL） | `syscall`（内部原语） |
|---|---|---|
| 目标 | 外部 OS DLL（IAT/ImplMap） | 编译器自带运行时（内建分发） |
| 声明位置 | 类内 import 块中 | 类内（`System.Runtime.Runtime`） |
| 名称 | 任意（可别名 entry） | 必须命中内置表 |
| 编码 | 可配置 charset | 编译器定死 UTF-16 |
| 调用约定 | cdecl/stdcall | 语言级（无约定概念） |

## 4. 语言特性二：import 块（强制类内 + 声明式归属）

### 4.1 语法

```cocoa
class Kernel32
{
    import kernel32.dll
    {
        static stdcall function GetTickCount(): int
        static stdcall function ExitProcess(exitCode: int)
    }
}

class User32
{
    import user32.dll charset = unicode       // 块级默认（可选键）
    {
        static stdcall function MessageBoxW(
            hWnd: int, text: string, caption: string, type: int): int
            extern(entry = MessageBoxA, charset = ansi)   // 函数级覆盖（括号可选）
        static stdcall function MessageBeep(uType: int): int
    }
}
```

### 4.2 规则

| 项 | 规则 |
|---|---|
| `import <dll> { ... }` | **只作类成员**；块内只允许 `static` extern 函数声明 |
| extern 强制 | extern 函数必须在类的 import 块内声明 + **必须 `static`**（对齐 C# `static extern`） |
| 旧写法废弃 | 顶层位置式 import / extern → 诊断错误（强制迁移） |
| 一类多块 | 一个类可有多个 import 块（每 DLL 一块） |
| 命名空间 | 允许类在 namespace 内（函数归命名空间 + 块 DLL） |
| 类纯净性 | 含 import 块的类：无实例字段/实例构造/实例方法/继承（供 native 放行判据） |

### 4.3 调用方式

```cocoa
function Main()
{
    Kernel32.GetTickCount()     // 类名限定调用，归属一眼可辨
    User32.MessageBeep(0)
}
```

## 5. 语言特性三：extern 元数据（entry 别名 + charset 编码）

### 5.1 语法：括号宽松（对齐 for/while 先例）

两种等价写法：

```cocoa
// 无括号（Cocoa 宽松风）
static stdcall function MessageBoxW(...): int
    extern entry = MessageBoxA, charset = ansi

// 有括号（显式分组风）
static stdcall function MessageBoxW(...): int
    extern(entry = MessageBoxA, charset = ansi)

// 块级：同样括号可选
import user32.dll charset = unicode
import (user32.dll charset = unicode)
```

### 5.2 键语义

| 键 | 缺省 | 说明 |
|---|---|---|
| `entry` | = 函数名 | DLL 导出名 ≠ Cocoa 名时映射；`FunctionSymbol.EntryPoint` |
| `charset` | 块级配置（缺省 unicode） | `ansi` / `unicode` / `auto` |
| 未来扩展 | — | `setlasterror` / `exactspelling` 等键预留（未知键 → 诊断错误） |

### 5.3 后端落点

- `FunctionSymbol.EntryPoint` → `IrImport` / ImplMap 用 `EntryPoint ?? Name`
- `FunctionSymbol.CharSet` → IL `ImplMap.MappingFlags` CharSet 位（`MetadataBuilder.cs` 当前写死 `CharSetAnsi 0x0002`，改为可配置）
- native 遇 `charset = ansi` → 编译期诊断"未实现"（不静默错编）；unicode 全链路（互操作手册 §2.6 已通）
- `auto` 映射 unicode

## 6. 隐式注入移除（C# 式强隔离）✅ Step 3（2026-08-22）

- `Binder.CreateRootScope`（`Binder.cs:1536`）删除 `BuiltinFunctions.GetAll()` 注入
- 用户须 `using System.Console` 才能 `WriteLine`（对齐 C#：无全局 `System` 隐式 using）
- `print`/`input`/`random` 全局裸名不可用，全部经 `System.Console` 等封装层
- 迁移面：全库测试/样例约 30 文件（`samples/Tutorial` 16 文件 + 测试 ~14 文件）`print(...)` → `System.Console.WriteLine(...)` / `System.Runtime.*`
- **顺带修复 x86 用户函数 double ABI 缺陷**：`EmitStoreArg`/`EmitInitParam`/`EmitStoreRet`/`EmitRet`/`StoreCallResult` 在 x86 按 8 字节双 dword 搬运；参数区 `ReserveArgs`/`StoreArg`/`InitParam`/`FreeArgs` 改用字节偏移（double 占 2 槽，x64 每参 8B 不变）；double 返回约定 EDX:EAX（低 dword 在 EAX）——此前 x86 下 `System.Console.WriteLine(5.5)` 打印 0（`Mov(Qword,...)` 在 X86 汇编器静默降级 32 位）
- **SystemLibrary 缓存加锁**：`Load()` 静态缓存非线程安全，并行编译竞态可致系统库偶发降级（编译产出 spurious 诊断）

## 9. 新增原语表（Step 1）

`BuiltinKind` 扩展 + 三后端各 1 case：

| 原语 | 签名 | Evaluator | IL | native Runtime |
|---|---|---|---|---|
| print | `(text: any): void` | `Console.WriteLine` | `Console.WriteLine` | PrintString/PrintInt/... |
| input | `(): string` | `Console.ReadLine` | `Console.ReadLine` | Input |
| random | `(max: int): int` | `Random.Shared.Next` | `new Random().Next` | Random |
| sleep | `(ms: int): void` | `Thread.Sleep` | `Thread.Sleep` | Sleep（kernel32） |
| now | `(): int` | `Environment.TickCount` | `Environment.get_TickCount` | GetTickCount |
| exit | `(code: int): void` | `Environment.Exit` | `Environment.Exit` | ExitProcess |

## 11. 决策记录

| 决策 | 结论 |
|---|---|
| 内部核心库 | **单一核心程序集** `System.Core.cod`（6e-M17 修订，由 `System.cod` 改名）：承载全部核心库内容，仿 .NET `System.Private.CoreLib`；不按 Math/String/Array 拆实现程序集（C# 亦不拆） |
| 多程序集机制 | **目录发现 `System*.cod`**（`System.Core.cod` 强制首位）；未来大功能模块各配 `.coproj` 构建放入目录即自动加载（仿 C# `System.Net.Http`/`System.Text.Json` 独立实现程序集）；各模块须自包含（库体内禁止跨 `.cod` 调用） |
| syscall 声明位置 | 类内（`System.Runtime.Runtime`），命名空间内类亦可 |
| 隐式注入 | 移除，C# 式强隔离（`using System.Console` 才可用 WriteLine） |
| 可命中范围 | 顺带扩展原语表（sleep/now/exit 起步） |
| extern 归属 | 强制类内 import 块 + 强制 static |
| import 块 | 作类成员，块级 `charset` 键可选；一类可多块 |
| 旧写法 | 顶层位置式 import/extern 废弃为诊断错误 |
| extern 元数据 | `extern(entry=, charset=)` 括号可选，命名键值，未来键预留 |
| 编码深度 | 语法全落地；unicode 全链路；native ansi 报"未实现"；auto=unicode |
| SetLastError | 首批不做，文档记扩展位 |
| native 容器类 | 放行"纯 extern/syscall 容器类"（无实例成员/构造/字段/继承），透明分组 |
