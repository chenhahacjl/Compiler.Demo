## 1. 概述

Cocoa 是一个自研编译器，支持两条后端路径：

- **Native 路径**：x86 / x64 机器码 + 自研 PE 输出（零第三方依赖）
- **IL 路径**：ECMA-335 IL（自研编码器 + 元数据写入器，阶段 5 完成）
- **IL 互操作**：native DLL 经 ImplMap/ModuleRef 消费（阶段 5-5 落地）；Native 路径导入表（阶段 6）

支持：

- 直接编译 `.co` 源文件
- 通过 `.coproj` 项目文件组织多源文件项目
- 通过 `.cosln` 解决方案文件组织多项目解决方案
- 三种输出格式：`executable` / `library` / `cocoa`
- native DLL 导入（`import`）、`.cod` 程序集引用（`-r`/`[references]` + `using`，阶段 6b）
- 增量构建（阶段 6）

### 工具链组成

| 工具 | 用途 |
|------|------|
| `cocoa` | 命令行编译器 + 项目管理（`new`/`list`/`add reference`/`remove reference`/`run`/`clean`）+ 交互式 REPL（`-i`） |
| `cocoa.exe` | 便捷调用脚本（`src/cocoa.cmd`） |

## 3. 编译器命令行 (`cocoa`)

### 3.1 命令总览

```bash
cocoa new <name> [-t <template>] [-o <dir>] [options]   # 创建项目 / 解决方案
cocoa build <project|solution> [options]                # 项目 / 解决方案构建（仅 .coproj / .cosln）
cocoa run [-p <project|solution>] [args...]             # 构建并运行产物
cocoa list <templates|projects|references> [-p <path>]  # 查看模板 / 项目 / 引用
cocoa add reference [-p <project>] <path>               # 添加引用
cocoa remove reference [-p <project>] <path>            # 移除引用
cocoa clean [-p <project|solution>]                     # 清理缓存（.cocoa/）与输出
cocoa -i                                                # 交互式 REPL（等价 --interactive）
cocoa <source> [options]                                # 直接编译单文件 / 多文件（兼容形态）
```

### 3.2 `new` — 创建项目

```bash
cocoa new [<template>] [name] [-n <name>] [-o <dir>] [--dotnet-runtime <tfm>]
```

仿 `dotnet new`：模板名（`console` 默认）作第一位置参数；项目名取 `-n <name>`（或第二位置参数 `name`，缺省为 `-o <dir>` 的目录名 / 当前目录名）。`-o <dir>` 指定输出目录（缺省为 `<name>/` 子目录）；目标文件已存在时报错。

| 模板 | 生成内容 |
|------|---------|
| `console`（默认） | `<name>.coproj`（`output = executable`、`entry = Main`、`dotnetRuntime = net48`）+ `main.co`（Hello World） |
| `library` | `<name>.coproj`（`output = library`）+ 导出函数源码 |
| `cocoa` | `<name>.coproj`（`output = cocoa`）+ 含 `namespace <Name>` 的源码（`.cod` 库） |
| `csharp` | `<name>.coproj`（`output = executable`、`[sources] *.cs`）+ `main.cs`（C# 方言：`namespace <Name>;` + `public static void Main()`，6e-M15） |
| `solution` | `<name>.cosln` + 内建 console 子项目 `<name>/<name>.coproj` |

```bash
cocoa new                       # 当前目录创建 console 项目（名 = 目录名）
cocoa new library MyLib         # 位置参数：模板 + 名称
cocoa new csharp MyApp          # C# 方言项目（.cs 源文件，6e-M15）
cocoa new console -n Hello -o hello/   # -n / -o 显式指定（仿 dotnet new）
cocoa new solution MySol        # 解决方案 + 子项目
```

### 3.3 `list` — 查看

```bash
cocoa list templates                      # 列出内置模板
cocoa list projects [-p <solution|目录>]  # 列出解决方案项目；默认当前目录
cocoa list references [-p <project|solution>]  # 列出引用（cosln 按项目聚合）
```

### 3.4 `add reference` / `remove reference` — 引用管理

```bash
cocoa add reference [-p <project>] <path>     # 追加到 [references]（无该节则创建，重复引用跳过）
cocoa remove reference [-p <project>] <path>  # 移除匹配引用
```

### 3.5 `run` / `clean`

```bash
cocoa run [-p <project|solution>] [args...]   # 先构建，再运行产物（cosln 须恰好一个 executable 项目）
cocoa clean [-p <project|solution>]           # 删除 .cocoa/ 缓存与输出目录
```

### 3.6 build 与直接编译

`cocoa build` 的输入支持：

| 输入 | 行为 |
|------|------|
| `MyApp.coproj` | 编译项目 |
| `MyApp.cosln` | 编译解决方案（`.cod` 项目引用拓扑排序） |

直接编译形态（`cocoa`）输入支持：

| 输入 | 行为 |
|------|------|
| `hello.co` | 编译单文件（`.co` 严格纯 Cocoa 方言：仅 Cocoa 式写法，6e-M16） |
| `hello.cs` | 编译单文件（`.cs` 严格 C# 方言，见 `语法手册.md` §46；6e-M15） |
| `a.co b.co c.cs` | 编译多文件（逐文件按扩展名分派解析器，可混排） |

> **扩展名即语言（6e-M15 / 6e-M16）**：`.cs` → `CSharpParser`（严格 C# 方言子集，仅 C# 式拼写、分号必选）；`.co` → `CocoaParser`（**严格纯 Cocoa**，仅 Cocoa 式拼写、分号可选）。同一项目 `[sources]` 可混排 `*.co` / `*.cs`。详见 `语法手册.md` §46。

#### 选项说明

| 选项 | 说明 | 示例 |
|------|------|------|
| `-p <path>` / `--path` | 项目/解决方案文件（与位置参数等价） | `cocoa build -p foo.coproj` |
| `-f <format>` / `--format` | 输出格式：`executable`（默认）/ `library` / `cocoa` | `cocoa build -p foo.coproj -f library` |
| `--platform <x86\|x64>` | Native 目标平台（默认 x64） | `cocoa --platform x86 hello.co` |
| `-o <path>` / `--output` | 输出路径 | `-o output.exe` |
| `-r <path>` / `--reference` | 引用（可多次），供 `using` 消费：`.coproj` 项目引用（自动递归构建 + 产物复制到生成目录）/ `.dll` 跨语言桥 / `.cod` Cocoa 程序集 | `-r ../Libs/MyLib.coproj` |
| `-b <name>` / `--backend` | 代码生成后端：`dotnet`（默认）/ `native` | `cocoa build -p foo.coproj -b dotnet` |
| `--dotnet-runtime <tfm>` | .NET 目标框架（仅 dotnet 后端）：`net40` / `net48`（默认，netfx）/ `net8.0` / `net9.0`（netcore） | `cocoa build -p foo.coproj --dotnet-runtime net9.0` |
| `--dotnet-module <name>` | 模块名（仅 dotnet 后端；默认取输出文件名） | `cocoa main.co --dotnet-module mylib` |
| `--no-incremental` | 强制全量构建 | `cocoa build -p foo.coproj --no-incremental` |
| `--debug` / `--release` | 构建模式（默认 release） | `cocoa build -p foo.coproj --debug` |
| `-i` / `--interactive` | 启动交互式 REPL | `cocoa -i` |
| `-?` / `-h` / `--help` | 帮助 | `cocoa -h` |

### 3.7 示例

```bash
# 创建项目（模板 + 名称，仿 dotnet new）
cocoa new console MyApp
cocoa new library MyLib
cocoa new solution MySol

# 单文件 → exe
cocoa hello.co

# 指定平台与输出
cocoa --platform x86 hello.co -o hello-x86.exe

# 项目 / 解决方案
cocoa build -p src/MyApp/MyApp.coproj
cocoa build -p src/MyApp.cosln

# 仓库自带样例（Tutorial：每功能块一个 exe 的解决方案 / 单项目）
# coproj 默认 dotnetRuntime = net48 → 构建后直接运行（netfx），无需 dotnet 前缀
cocoa build -p samples/Tutorial/Tutorial.cosln
cocoa build -p samples/Tutorial/HelloWorld/HelloWorld.coproj
./samples/Tutorial/HelloWorld/out/HelloWorld.exe

# .cod 语义层程序集闭环（samples/CodLibrary：cocoa 库 → [references] 消费，native + dotnet 双后端）
# mylib output=cocoa → .cod；app [references] 引用 → 编译期 IR 合并 → 独立 exe（CopyLocal 自动复制 .cod）
# 默认 dotnetRuntime = net48（netfx），产物直接运行（无需 dotnet 前缀）
cocoa build -p samples/CodLibrary/mylib/MyLib.coproj
cocoa build -p samples/CodLibrary/app/App.coproj -b native
./samples/CodLibrary/app/out/App.exe
cocoa build -p samples/CodLibrary/app/App.coproj -b dotnet
./samples/CodLibrary/app/out/App.exe

# 指定后端与平台
cocoa build -p foo.coproj -b dotnet
cocoa build -p foo.coproj --platform x86

# 指定 .NET 目标框架（netcore 版本化；默认 net48 netfx 直接运行）
cocoa build -p foo.coproj --dotnet-runtime net9.0

# 输出 library（dll 输出格式，供其他项目 -r 引用消费）
cocoa build -p mylib.coproj -f library

# 引用项目（coproj 项目引用：自动构建 + 产物复制到当前生成目录）
cocoa build -p app.coproj -r ../Libs/mylib.coproj

# 引用 .NET 库（dll），配合源码里的 using 消费外部类型
cocoa build -p app.coproj -r ../Libs/mylib.dll

# 交互式 REPL
cocoa -i
```

## 4. 项目文件 (`.coproj`)

采用**轻量文本格式**（非 JSON）。完整规范见 [`docs/项目格式规范.md`](项目格式规范.md)。

```
name = MyApp
output = executable
platform = x64
entry = main
dotnetRuntime = net48

[sources]
src/*.co

[references]
../Libs/MyLib.coproj   # 项目引用（自动构建 + 产物复制到生成目录）
lib.cod                # Cocoa 程序集（阶段 6b）
mylib.dll              # .NET 程序集（跨语言桥）

[imports]
kernel32.dll

[options]
incremental = true
debug = false
outputPath = bin
```

| 字段 | 说明 |
|------|------|
| `name` | 项目名（默认 = 文件名） |
| `output` | `executable` / `library` / `cocoa` |
| `platform` | `x86` / `x64` |
| `entry` | 入口函数（仅 exe；默认 `main`）。可为顶层函数名，或 `ClassName.Method` / `Namespace.ClassName.Method`（类静态方法）；带参形式须是 `function entry(args: string[])` |
| `dotnetRuntime` | .NET 目标框架 TFM：`net40` / `net48`（默认，netfx 直接运行）/ `net8.0` / `net9.0`（netcore，仅 dotnet 后端） |
| `[sources]` | 源文件 glob 列表 |
| `[references]` | 引用列表（每行一个）：`.coproj` 项目引用（自动递归构建 + 产物复制到当前生成目录，仅 `cocoa`/`library` 可被引用）/ `.cod` Cocoa 程序集 / `.dll` 跨语言桥 |
| `[imports]` | native DLL 列表 |
| `[options]` | 增量/调试/输出目录 |

**用户级覆盖 `.coproj.user`**：同一目录下 `<项目名>.coproj.user`（gitignored 不入库）可按个人/机器覆盖
顶层属性与 `[options]`，优先级 `.coproj` < `.coproj.user` < 命令行参数；未知节/键忽略（IDE 预留）。
详见 [`docs/项目格式规范.md`](项目格式规范.md) §3.1。

## 5. 解决方案文件 (`.cosln`)

```
name = MyApp

[projects]
src/Core/Core.coproj
src/App/App.coproj
```

编译顺序由项目间引用关系拓扑排序决定：`[references]` 中的 `.coproj` 路径（全路径匹配项目文件）与 `.cod`/`.dll` 产物路径均建依赖边（`output = cocoa` 项目参与依赖图，先编译被引用者）；无依赖时按声明顺序；检测到循环依赖报错。

## 7. 增量构建

- 默认开启（`incremental = true`）
- 缓存**集中**存放：解决方案构建 → `<解决方案目录>/.cocoa/<项目相对路径>/<name>.cache`；
  单项目 → `<项目目录>/.cocoa/<name>.cache`（仿 `.vs/`，一个 `.cocoa/` 目录收纳全部状态，产物 exe 不受影响）
- 缓存内容：源文件内容 SHA-256 + glob 展开 + 引用元数据 + imports + 选项快照
- 全命中 → "up to date"；部分变化 → 仅重编相关项目
- `--no-incremental` 强制全量；删除 `.cocoa/` 后全量重建

## 9. Cocoa 语言快速入门

### 9.1 Hello World

```cocoa
// hello.co
function Main()
{
    System.Console.WriteLine("What's your name?")
    let name = input()
    System.Console.WriteLine("Hello " + name + "!")
}
```

```bash
# netcore（默认）：原生 apphost 直接运行（双击/命令行均可，dotnet 前缀亦可）
cocoa hello.co
./hello.exe          # apphost 直接运行
dotnet ./hello.dll   # 等价：dotnet 宿主运行托管程序集

# netfx：Windows 直接运行（.NET Framework 4.x，无需 dotnet 前缀）
cocoa hello.co --dotnet-runtime net48
./hello.exe
```

### 9.2 变量与类型

```cocoa
let x = 42              // 不可变
var y = 10              // 可变
let name: string = "Alice"
var count: int = 0
let a: int = 42
let b: double = 3.14
let c: bool = true
```

### 9.3 控制流

```cocoa
if (x > 0) { System.Console.WriteLine("positive") }
else if (x == 0) { System.Console.WriteLine("zero") }
else { System.Console.WriteLine("negative") }

var i = 0
while (i < 10) { System.Console.WriteLine(i) i = i + 1 }

for var i = 0 to 5 { System.Console.WriteLine(i) }

do { System.Console.WriteLine("once") } while (false)
```

### 9.4 函数

```cocoa
function add(a: int, b: int): int { return a + b }

function factorial(n: int): int
{
    if (n <= 1) { return 1 }
    return n * factorial(n - 1)
}
```

**程序入口与命令行参数**：默认入口 `main`，可为无参形式或单参数组形式：

```cocoa
function Main(args: string[])
{
    System.Console.WriteLine(args.Length)
    System.Console.WriteLine(args[0])
}
```

`args` 是运行程序时传入的命令行参数（不含程序名），`args.Length` 为参数个数；
可用 `entry = xxx`（见第 4 章）把入口换成其他函数，带参入口写法同上（`function xxx(args: string[])`）。

入口也支持**类静态方法**，可写限定名（命名空间可选）：

```cocoa
// namespace My.App 内：public class Program { public static void Main() }
// coproj: entry = My.App.Program.Main（或省略命名空间：entry = Program.Main，类名全局唯一时）
```

带参类入口写法相同（`public static void Main(args: string[])`）。

### 9.5 导入 native DLL（阶段 6，6e-M17 Step 4/5）

```cocoa
// import 块作类成员：DLL 归属由块声明式绑定，调用用类名限定
class Kernel32
{
    import kernel32.dll
    {
        static stdcall function GetTickCount(): int
        static stdcall function ExitProcess(exitCode: int)
    }
}

function isRunning(): bool
{
    return Kernel32.GetTickCount() > 0
}
```

extern 元数据（6e-M17 Step 5）：`extern(entry = MessageBoxA, charset = ansi)`（括号可选）映射 DLL 导出名别名与编码；块级键 `import user32.dll charset = unicode` 设置块内函数缺省编码。

`export function` 尚未实现（dll 输出导出表条目，见阶段 7 计划），仅支持 `import`。

## 10. 常见问题

### 10.1 编译器报 "file doesn't exist"

检查源文件路径。支持相对路径和绝对路径。

### 10.2 崩溃 / 行为异常（Native x86）

阶段 0 的 x86 管道输入崩溃已于 2026-08-13 修复（`ImportResolverStubEmitter` 名字模板截断问题），
x86/x64 双平台基线全绿。如再遇崩溃，请携带复现输入提交 issue。

### 10.3 输出文件

| 格式 | 产物 |
|------|------|
| `executable` | `.exe` |
| `library` | `.dll` |
| `cocoa` | `.cod` |
| 调试 | `.pdb`（IL 路径）|

### 10.4 Native 输出重定向为 UTF-16

Native 路径 `System.Console.WriteLine`（→ `System.Runtime.WriteLine` 内部调用）在控制台走 `WriteConsoleW`（UTF-16）；当 stdout 被重定向到管道/文件时，
运行库直接写入原始 UTF-16LE 字节（`WriteFile`）。在 `cmd`/PowerShell 中直接运行不受影响；
若需 UTF-8 文本流请在各自进程内自行处理（后续版本计划对齐）。
