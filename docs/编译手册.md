## 1. 概述

Cocoa 是一个自研编译器，支持两条后端路径：

- **Native 路径**：x86 / x64 机器码 + 自研 PE 输出（零第三方依赖）
- **IL 路径**：ECMA-335 IL（自研编码器 + 元数据写入器，阶段 5 完成）
- **IL 互操作**：native DLL 经 ImplMap/ModuleRef 消费（阶段 5-5 落地）；Native 路径导入表（阶段 6）

支持：

- 直接编译 `.co` 源文件
- 通过 `.coproj` 项目文件组织多源文件项目
- 通过 `.cosln` 解决方案文件组织多项目解决方案
- 三种输出格式：`executable` / `library` / `cocoa`
- native DLL 导入（`import`）、`.cod` 程序集引用（`-r`/`[references]` + `using`，阶段 6b）
- 增量构建（阶段 6）

### 工具链组成

| 工具 | 用途 |
|------|------|
| `coc` | 命令行编译器 |
| `coi` | 交互式 REPL |
| `coc.exe` / `coi.exe` | 便捷调用脚本（`src/coc.cmd` / `src/coi.cmd`） |

## 3. 编译器命令行 (`coc`)

### 3.1 命令结构

```bash
coc build <project|copsln> [options]   # 项目/解决方案构建（阶段 6d，仅 .coproj / .cosln）
coc <source> [options]                 # 直接编译单文件/多文件（兼容形态）
```

`coc build` 的 `<source>` 支持：

| 输入 | 行为 |
|------|------|
| `MyApp.coproj` | 编译项目 |
| `MyApp.cosln` | 编译解决方案（`.cod` 项目引用拓扑排序） |

直接编译形态（`coc`）支持：

| 输入 | 行为 |
|------|------|
| `hello.co` | 编译单文件 |
| `a.co b.co c.co` | 编译多文件 |

### 3.2 选项说明

| 选项 | 说明 | 示例 |
|------|------|------|
| `-p <path>` / `--path` | 项目/解决方案文件（与位置参数等价） | `coc build -p foo.coproj` |
| `-f <format>` / `--format` | 输出格式：`executable`（默认）/ `library` / `cocoa` | `coc build -p foo.coproj -f library` |
| `--platform <x86\|x64>` | Native 目标平台（默认 x64） | `coc --platform x86 hello.co` |
| `-o <path>` / `--output` | 输出路径 | `-o output.exe` |
| `-r <path>` / `--reference` | 引用（可多次），供 `using` 消费：`.coproj` 项目引用（自动递归构建 + 产物复制到生成目录）/ `.dll` 跨语言桥 / `.cod` Cocoa 程序集 | `-r ../Libs/MyLib.coproj` |
| `-b <name>` / `--backend` | 代码生成后端：`dotnet`（默认）/ `native` | `coc build -p foo.coproj -b dotnet` |
| `--dotnet-runtime <tfm>` | .NET 目标框架（仅 dotnet 后端）：`net9.0`（默认）/ `net8.0` / `net4x` | `coc build -p foo.coproj --dotnet-runtime net8.0` |
| `--dotnet-module <name>` | 模块名（仅 dotnet 后端；默认取输出文件名） | `coc main.co --dotnet-module mylib` |
| `--no-incremental` | 强制全量构建 | `coc build -p foo.coproj --no-incremental` |
| `--debug` / `--release` | 构建模式（默认 release） | `coc build -p foo.coproj --debug` |
| `-?` / `-h` / `--help` | 帮助 | `coc -h` |

### 3.3 示例

```bash
# 单文件 → exe
coc hello.co

# 指定平台与输出
coc --platform x86 hello.co -o hello-x86.exe

# 项目 / 解决方案
coc build -p src/MyApp/MyApp.coproj
coc build -p src/MyApp.cosln

# 仓库自带样例（Tutorial：每功能块一个 exe 的解决方案 / 单项目）
# coproj 默认 dotnetRuntime = net40 → 构建后直接运行（netfx），无需 dotnet 前缀
coc build -p samples/Tutorial/Tutorial.cosln
coc build -p samples/Tutorial/HelloWorld/HelloWorld.coproj
./samples/Tutorial/HelloWorld/out/HelloWorld.exe

# 指定后端与平台
coc build -p foo.coproj -b dotnet
coc build -p foo.coproj --platform x86

# 指定 .NET 目标框架（netcore 版本化）
coc build -p foo.coproj --dotnet-runtime net8.0

# 输出 library（dll 输出格式，供其他项目 -r 引用消费）
coc build -p mylib.coproj -f library

# 引用项目（coproj 项目引用：自动构建 + 产物复制到当前生成目录）
coc build -p app.coproj -r ../Libs/mylib.coproj

# 引用 .NET 库（dll），配合源码里的 using 消费外部类型
coc build -p app.coproj -r ../Libs/mylib.dll
```

## 4. 项目文件 (`.coproj`)

采用**轻量文本格式**（非 JSON）。完整规范见 [`docs/项目格式规范.md`](项目格式规范.md)。

```
name = MyApp
output = executable
platform = x64
entry = main
dotnetRuntime = net9.0

[sources]
src/*.co

[references]
../Libs/MyLib.coproj   # 项目引用（自动构建 + 产物复制到生成目录）
lib.cod                # Cocoa 程序集（阶段 6b）
mylib.dll              # .NET 程序集（跨语言桥）

[imports]
kernel32.dll

[options]
incremental = true
debug = false
outputPath = bin
```

| 字段 | 说明 |
|------|------|
| `name` | 项目名（默认 = 文件名） |
| `output` | `executable` / `library` / `cocoa` |
| `platform` | `x86` / `x64` |
| `entry` | 入口函数（仅 exe；默认 `main`）。可为顶层函数名，或 `ClassName.Method` / `Namespace.ClassName.Method`（类静态方法）；带参形式须是 `function entry(args: string[])` |
| `dotnetRuntime` | .NET 目标框架 TFM：`net9.0`（默认）/ `net8.0` / `net4x`（仅 dotnet 后端） |
| `[sources]` | 源文件 glob 列表 |
| `[references]` | 引用列表（每行一个）：`.coproj` 项目引用（自动递归构建 + 产物复制到当前生成目录，仅 `cocoa`/`library` 可被引用）/ `.cod` Cocoa 程序集 / `.dll` 跨语言桥 |
| `[imports]` | native DLL 列表 |
| `[options]` | 增量/调试/输出目录 |

**用户级覆盖 `.coproj.user`**：同一目录下 `<项目名>.coproj.user`（gitignored 不入库）可按个人/机器覆盖
顶层属性与 `[options]`，优先级 `.coproj` < `.coproj.user` < 命令行参数；未知节/键忽略（IDE 预留）。
详见 [`docs/项目格式规范.md`](项目格式规范.md) §3.1。

## 5. 解决方案文件 (`.cosln`)

```
name = MyApp

[projects]
src/Core/Core.coproj
src/App/App.coproj
```

编译顺序由项目间引用关系拓扑排序决定：`[references]` 中的 `.coproj` 路径（全路径匹配项目文件）与 `.cod`/`.dll` 产物路径均建依赖边（`output = cocoa` 项目参与依赖图，先编译被引用者）；无依赖时按声明顺序；检测到循环依赖报错。

## 7. 增量构建

- 默认开启（`incremental = true`）
- 缓存**集中**存放：解决方案构建 → `<解决方案目录>/.coc/<项目相对路径>/<name>.cache`；
  单项目 → `<项目目录>/.coc/<name>.cache`（仿 `.vs/`，一个 `.coc/` 目录收纳全部状态，产物 exe 不受影响）
- 缓存内容：源文件内容 SHA-256 + glob 展开 + 引用元数据 + imports + 选项快照
- 全命中 → "up to date"；部分变化 → 仅重编相关项目
- `--no-incremental` 强制全量；删除 `.coc/` 后全量重建

## 9. Cocoa 语言快速入门

### 9.1 Hello World

```cocoa
// hello.co
function Main()
{
    print("What's your name?")
    let name = input()
    print("Hello " + name + "!")
}
```

```bash
# netcore（默认）：dotnet 宿主运行
coc hello.co
dotnet ./hello.exe

# netfx：Windows 直接运行（.NET Framework 4.x，无需 dotnet 前缀）
coc hello.co --dotnet-runtime net40
./hello.exe
```

### 9.2 变量与类型

```cocoa
let x = 42              // 不可变
var y = 10              // 可变
let name: string = "Alice"
var count: int = 0
let a: int = 42
let b: double = 3.14
let c: bool = true
```

### 9.3 控制流

```cocoa
if (x > 0) { print("positive") }
else if (x == 0) { print("zero") }
else { print("negative") }

var i = 0
while (i < 10) { print(i) i = i + 1 }

for var i = 0 to 5 { print(i) }

do { print("once") } while (false)
```

### 9.4 函数

```cocoa
function add(a: int, b: int): int { return a + b }

function factorial(n: int): int
{
    if (n <= 1) { return 1 }
    return n * factorial(n - 1)
}
```

**程序入口与命令行参数**：默认入口 `main`，可为无参形式或单参数组形式：

```cocoa
function Main(args: string[])
{
    print(args.Length)
    print(args[0])
}
```

`args` 是运行程序时传入的命令行参数（不含程序名），`args.Length` 为参数个数；
可用 `entry = xxx`（见第 4 章）把入口换成其他函数，带参入口写法同上（`function xxx(args: string[])`）。

入口也支持**类静态方法**，可写限定名（命名空间可选）：

```cocoa
// namespace My.App 内：public class Program { public static void Main() }
// coproj: entry = My.App.Program.Main（或省略命名空间：entry = Program.Main，类名全局唯一时）
```

带参类入口写法相同（`public static void Main(args: string[])`）。

### 9.5 导入 native DLL（阶段 6）

```cocoa
import kernel32.dll

stdcall function GetTickCount(): int

function isRunning(): bool
{
    return GetTickCount() > 0
}
```

`export function` 尚未实现（dll 输出导出表条目，见阶段 7 计划），仅支持 `import`。

## 10. 常见问题

### 10.1 编译器报 "file doesn't exist"

检查源文件路径。支持相对路径和绝对路径。

### 10.2 崩溃 / 行为异常（Native x86）

阶段 0 的 x86 管道输入崩溃已于 2026-08-13 修复（`ImportResolverStubEmitter` 名字模板截断问题），
x86/x64 双平台基线全绿。如再遇崩溃，请携带复现输入提交 issue。

### 10.3 输出文件

| 格式 | 产物 |
|------|------|
| `executable` | `.exe` |
| `library` | `.dll` |
| `cocoa` | `.cod` |
| 调试 | `.pdb`（IL 路径）|

### 10.4 Native 输出重定向为 UTF-16

Native 路径 `print` 在控制台走 `WriteConsoleW`（UTF-16）；当 stdout 被重定向到管道/文件时，
运行库直接写入原始 UTF-16LE 字节（`WriteFile`）。在 `cmd`/PowerShell 中直接运行不受影响；
若需 UTF-8 文本流请在各自进程内自行处理（后续版本计划对齐）。
