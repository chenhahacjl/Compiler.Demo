# Cocoa 输出格式规范

> 适用范围：`-f exe` / `-f library` / `-f cocoa` 三种输出
> 状态：`exe` 已实现（Native/IL）；`library`（.NET 托管 dll）已实现（M3，供 `-r` 消费）；`cocoa`（.cod 语义层程序集）设计中（阶段 6b）
> 注：`-f library` 产出 **.NET 托管 dll**（class/继承/属性，供 `-r` + `using` 消费）。本文档「native 导出库」（`-f dll`，导出符号 + 重定位）是另一概念，仍待实现。
> 最后更新：2026-08-20

---

## 1. 总览

| 格式 | 输出物 | 角色 | 消费方式 |
|------|--------|------|---------|
| `cocoa` | `.cod`（语义层程序集，平台无关） | **Cocoa 内部库**：编译期合并（BoundProgram），native/IL 通用，无 ABI 风险 | 编译期 `-r a.cod` + `using` |
| `library` | .NET 托管 dll（public 类/成员元数据） | **跨语言桥**：C# 等 .NET 生态消费 | 编译期 `-r` + `using`（运行期元数据加载） |
| `exe` | PE 可执行文件（Native 或 IL 程序集） | 独立运行 | 直接执行 |
| `dll` | Native 导出库（导出表 + 重定位） | 被其他程序/库调用 | 运行期 `import` → 导入表（待实现） |

```bash
cocoa build -p foo.coproj -f executable|library|cocoa
```

格式选择优先级（coproj 内配置与 `-f` 命令行，命令行优先）。

### 1.1 `.cod` 程序集语义（等价 .NET dll）

`.cod` 是 Cocoa 的"程序集"分发格式：

- **每库一个/多个 `namespace`**：公共符号表按命名空间组织（public 类型/函数/枚举/全局变量）
- **无入口点**：`output = cocoa` 项目禁止 `Main`/入口，源码须含 `namespace`（违者编译报错）
- **依赖**：可引用其他 `.cod`（依赖清单递归加载，库套库）、.NET 程序集、native DLL；可被 `.cod`/`library`/`executable` 项目引用
- **平台无关**：存平台无关 IR，消费方按自己的后端/平台把合并后的 IR 编译成最终产物

### 1.2 平台产物命名

| 格式 | Windows | Linux |
|------|---------|-------|
| `cocoa` | `a.cod`（平台无关） | `a.cod`（平台无关） |
| `library` | `b.dll` | `b`（共享库 `libb.so`） |
| `executable` | `c.exe` | `c` |

- IL 后端（`-b dotnet`）产物在 Linux 天然可运行（dotnet 跨平台）；native 后端 Linux 需 ELF 输出（规划中，与 `PefileWriter` 对称）
- 纯 Cocoa 的 `.cod` 跨平台；含 native import（如 `kernel32.dll`）的 `.cod` 绑定平台（依赖清单平台校验，不匹配报错）

## 2. `exe`

### 2.1 Native 路径

- PE32/PE32+：`.text` / `.data` / `.idata` 三 section（`PefileWriter`）
- 入口 stub → `main`；导入表（kernel32 的 I/O 函数）
- x86 输出带 `RelocsStripped`（当前可执行文件无重定位，阶段 6 的 dll 需写侧重定位）
- 平台：`--platform x86|x64`

### 2.2 IL 路径

- 托管 PE（自研编码器 + 元数据写入器，阶段 5 完成；互操作走 ImplMap，见 `互操作手册.md` §2.5）
- netcore（默认）：AMD64 托管 `x.dll` + runtimeconfig + 原生 apphost `x.exe`（SDK 同款占位符修补，`AppHostPatcher`），Windows 直接运行 `x.exe`（`dotnet x.dll` 亦可）
- netfx（`--dotnet-runtime net4x`）：I386/PE32（AnyCPU）+ mscoree 导入，Windows 直接运行 `x.exe`
- 调试模式产出 `.pdb`

## 3. `dll`

Native 导出库（阶段 6b）。与 exe 的差异：

| 组件 | exe（现状） | dll（新增） |
|------|------------|------------|
| 导出表 `PeExportTable` | 读侧（解析 exe/dll 的导入） | **写侧**（生成导出目录） |
| 重定位表 `PeRelocTable` | 读侧 | **写侧**：基址重定位 |
| 重定位类型 | — | x86: `HIGHLOW`(3)；x64: `DIR64`(10) |
| 符号导出 | — | `export fn` 语法标记 |

### 3.1 `export` 语法

```cocoa
export function Add(a: int, b: int): int { return a + b }
export var version: int = 1
```

- `export` 修饰的函数/变量进入导出表（名称 + RVA）
- 与 `import` 配对：dll 导出 → 消费者 `import foo.dll` → 导入表引用（统一机制）

### 3.2 导出表生成流程

```
1. 收集 export 符号（名称 → 最终 RVA）
2. 生成导出目录（ExportDirectoryTable + 名称表 + 序数表）
3. 重定位扫描：所有指向自身 ImageBase 的绝对地址项
   x86 → HIGHLOW；x64 → DIR64
4. 新增 .edata section 或并入现有 section（定稿时确定）
```

### 3.3 入口要求

- `output = dll` 的项目无需入口函数（可省略 `entry`）
- 若含 `main` 且未 export，不导出

## 4. `cocoa`（.cod 语义层程序集）

`.cod` = 平台无关语义层程序集（Cocoa 内部库/系统库分发），详见 `docs/项目格式规范.md` §4。

```
COCOD 头（魔数 + 版本 + 平台要求 + backend 要求 requires）
依赖清单（.NET 程序集引用 + native 导入列表 + 被引用的 .cod，见 项目格式规范.md §4.1）
公共符号表（public 类型/函数/枚举/全局变量，按命名空间组织）
代码区（序列化 BoundProgram 语义层：函数体 + 类成员 + 私有依赖闭包）
```

- 生成：`-f cocoa` 时编译到 BoundProgram 即停，输出 `.cod`（跳过 IR/机器码/IL 生成）；`requires` 由库内容推导（含 .NET API/OOP → dotnet；含 native import → 平台绑定；纯函数 → any）
- 消费：`[references]` / `-r` 加载 → 反序列化 → 符号并入 Binder + BoundProgram 层合并（`requires`/平台编译期校验）→ 递归加载被引用 `.cod` → 按消费方后端发射独立 dll/exe
- 与 dll 的取舍：
  - `cocoa` = 编译期合并（类似 C++ 模块单元/静态库），无 ABI 风险，native 后端对象分发唯一途径
  - `dll` = 运行期二进制互操作（C ABI 层），用于跨语言调用
  - `library`(.NET dll) = 跨语言桥（C# 消费），与 `.cod` 互补

## 5. 依赖关系

| 阶段 | 依赖 | 输出 |
|------|------|------|
| 现 | IR 定稿 | `exe`（Native/IL）、`library`（.NET dll） |
| 阶段 6b | BoundProgram 语义层序列化 | `cocoa`（.cod 语义层程序集） |
| 后续 | IR + 写侧导出/重定位 | `dll`（native 导出库）、Linux ELF |
