## 1. 目标与范围

现状四个结构性问题，本文档为治理依据：

1. **`Emitter.cs` 名称/位置错位**：内容 100% 是 IL 发射，却用通用名 `Emitter`、放 `Emit/` 根目录、命名空间 `Cocoa.CodeAnalysis.Emit`——与 IL 侧兄弟组件（`IlAssembler`/`IlInstruction`/`IlOpCode` 等在 `Emit/IL/` + `...Emit.IL`）不一致。
2. **`Emit/IR/` 目录名误导**：内容 100% native 专用（`BoundTreeToIr`/`IrToAssembler`/`RuntimeEmitterIR` 等），但 "IR" 名暗示双后端共享中间层（开发计划阶段 1-3 的原设想）。落地事实是：IL 后端绑定树直达，不消费 IR。
3. **X64/X86 平台文件不对称**：`X64/Runtime.cs`（类 `RuntimeEmitter`）缺 `.X64` 后缀，与 `X86/Runtime.X86.cs`（类 `RuntimeEmitterX86`）不对称；也违反 `X64Assembler`/`X86Assembler` 的既有惯例。
4. **文件名/类名不一致**：`PEFile.cs` 内类名 `PefileWriter`（`Pe` 大小写错位）；`RuntimeEmitterIR.cs` 内私有类名 `Emitter`（与 IL `Emitter` 同名混淆）。

**范围**：仅目录/命名空间/类名治理（零逻辑改动），不改变任何行为。功能层/逻辑层的职责划分见 §5，stdlib 设计见 `docs/标准库设计.md`。

## 2. 目录规范

```
src/Cocoa/CodeAnalysis/
  Emit/
    IL/                 # IL 后端组件（Il* 前缀 + Metadata*/ManagedPEWriter/AppHostPatcher）
    Native/             # native 后端
      IR/               # native IR 模型 + 绑定树→IR→汇编（Ir* 前缀 + BoundTreeToIr/RuntimeEmitterIR）
      Assembler/        # X64/X86 汇编器（IAssembler 接口）
      PEFile/           # PE 镜像写入（Pe* 前缀）
      Runtime/          # 平台运行时（Windows/X64|X86 对称）
```

- `Emit/` 根目录**不放 .cs**（`Emitter.cs` 迁入 `Emit/IL/` 后根目录清空）。
- IR 是 **native 管线内部层**，不是后端共享中间层；归入 `Emit/Native/IR/`，命名空间 `Cocoa.CodeAnalysis.Emit.Native.IR`。

## 3. 命名约定

| 类别 | 前缀/后缀 | 示例 |
|------|-----------|------|
| IL 组件 | `Il` 前缀 | `IlAssembler`/`IlEmitter`/`IlInstruction`/`IlOpCode`/`IlOpCodeTable`/`IlTarget`/`IlReferenceResolver` |
| native IR 模型 | `Ir` 前缀 | `IrProgram`/`IrOpCode`/`IrCond`/`IrInstruction`/`IrVirtualRegister`/`IrPrinter` |
| PE 层 | `Pe` 前缀 | `PeHeaders`/`PeImage`/`PeImportTable`/`PeFileWriter`/`PeExportTable`/… |
| 平台对称 | `X64`/`X86` 后缀 | `X64Assembler`/`X86Assembler`、`RuntimeEmitterX64`/`RuntimeEmitterX86` |
| 文件名 == 主类名 | 大小写一致 | `PeFileWriter.cs` ↔ `PeFileWriter` |
| 后端入口 | 职责名 | `IlEmitter`（IL）/ `NativeCodeEmitter`（native）/ `Evaluator`（解释器） |

**约定细则**：
- IL 组件统一 `Il` 前缀（`IlOpCode` struct + `IlOpCodeTable` 静态表，消除复数 `IlOpCodes` 歧义）。
- 平台对称文件：`Runtime.X64.cs` ↔ `Runtime.X86.cs`（均带架构后缀）。
- 绑定树→后端代码：native 用 `BoundTreeToIr`（`XxxToYyy` 管线风格）；IL 直达，入口 `IlEmitter`。
- 内部私有类不与全局类重名（`RuntimeEmitterIR` 内私有类改名 `RuntimeFunctionEmitter`）。

## 4. native/IL 功能对应

| 功能 | native | IL |
|------|--------|----|
| 后端入口编排 | `NativeCodeEmitter` | `IlEmitter` |
| 绑定树 → 后端代码 | `BoundTreeToIr`（经 IR） | `IlEmitter`（直达，无 IR 层） |
| "运行时实现" | `RuntimeEmitterIR`（自研运行时函数 IR） | `IlFramework`（.NET 方法引用集中，stdlib P0 拆出） |
| 指令 → 字节 | `IrToAssembler` + `X64Assembler`/`X86Assembler` | `IlAssembler`（IL 指令 → 字节） |
| 操作码 | `IrOpCode`（enum） | `IlOpCode`（struct）+ `IlOpCodeTable`（表） |
| PE/镜像写入 | `PeFileWriter` + `Pe*` 表 | `ManagedPEWriter` + `MetadataBuilder`/`MetadataReader` |
| 平台运行时 | `RuntimeEmitterX64`/`RuntimeEmitterX86`（Windows） | .NET 运行时 |

> 注：IL 侧 `ManagedPEWriter`/`Metadata*` 与 native `Pe*` 命名风格不同是历史演进（阶段 5 自研写入器），语义对应但暂不对齐。

## 5. 功能层 vs 逻辑层

| 层 | 定义 | 归属 | 后端映射 |
|----|------|------|---------|
| **功能层** | 语言不可约的后端能力原语 | 编译器内置（`BuiltinFunctions` 规格表 + `FunctionSymbol.BuiltinKind`） | Evaluator：C# 直接实现；IL：.NET API（`IlFramework`）；native：自研运行时函数（`RuntimeEmitterIR`） |
| **逻辑层** | 可表达计算的标准库函数 | Cocoa 源码 → `.cod`（`src/stdlib/`） | 三后端零改动（语义层 BoundProgram 合并） |

- **功能层**：`print`/`input`/`random`（+ 未来 `sqrt`/`pow` 等数学原语）。新增原语 = 1 行规格 + 三后端各 1 个 kind case + 1 个 IL 方法引用。
- **逻辑层**：`System.Math`/`System.String`/`System.Array` 等，只依赖语言核心 + 功能层原语，跨后端一致。
- 边界判定：能被现有语言特性（算术/字符串/数组/控制流）表达的 → 逻辑层；需要后端特殊服务（I/O/随机/硬件指令）的 → 功能层。

## 6. 治理清单（现状 → 目标）

| 项 | 现状 | 目标 | 阶段 |
|----|------|------|------|
| A1 | `Emit/Emitter.cs`（根，`.Emit`，类 `Emitter`） | `Emit/IL/IlEmitter.cs`（`.Emit.IL`，类 `IlEmitter`） | Phase 1 |
| A3 | `Native/Runtime/Windows/X64/Runtime.cs`（类 `RuntimeEmitter`） | `Runtime.X64.cs`（类 `RuntimeEmitterX64`，对齐 X86） | Phase 1 |
| A4 | `Native/PEFile/PEFile.cs`（类 `PefileWriter`） | `PeFileWriter.cs`（类 `PeFileWriter`） | Phase 1 |
| A5 | `IR/RuntimeEmitterIR.cs` 内部私有类 `Emitter` | 内部类 `RuntimeFunctionEmitter`（消同名混淆） | Phase 1 |
| A2 | `Emit/IR/`（8 文件，`.Emit.IR`） | `Emit/Native/IR/`（`.Emit.Native.IR`） | Phase 2 |
| P0-a | `BuiltinFunctions` 三后端散落 `== BuiltinFunctions.X` 引用相等 | `BuiltinKind` 规格表 + 三后端 kind 分发 | Phase 2 |
| P0-b | IL 侧 .NET 方法引用揉在 `IlEmitter` ctor + `IlOpCodes` 复数表 | `IlFramework` 集中 + `RequireType` 缓存 + `IlOpCodeTable` | Phase 2 |

**治理顺序**：Phase 1（纯改名零逻辑，A1→A3→A4→A5）→ Phase 2（结构移位 + 功能层抽象：A2 + P0-a + P0-b）。

- 全量测试通过（当前 26699 用例，每提交独立回归）。
