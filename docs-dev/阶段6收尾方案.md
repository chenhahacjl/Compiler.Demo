### 关键机制现状（调研摘录，执行时对照）

- **Encode v3 类型编码**：`CoaSerializer.Symbols.cs` `TypeRef`（:327-414）——基元 `@i32` 记法；开放参数 `!属主全名.名`（属主 = `TypeParameterSymbol.OwningClass`，TypeParameterSymbol.cs:23-24）；实例化 `Def`N#$args`（GenericTypeInstantiator.cs Encode :226-235 与序列化共用同一编码，mangle/CacheKey 同源）。读侧 `Resolve.cs` `!` 分支（:115-129）查 `OpenTypeParametersByKey`（每 .coa 文件一份平铺表，Read.cs:220-221/482）。
- **foreach 策略点**：`BindForeachStatement`（CocoaBinder.Statements.cs:1160-1346）三路——数组索引循环 / string 逐 char / 枚举器模式。`FindEnumeratorClass`（:1245-1279）走"具体枚举器类"策略：`GetEnumerator` 返回类型即枚举器符号，接口仅作能力标记；另有"直接模式"（:1258-1265，返回类型带 MoveNext+Current 即可，不要求实现 IEnumerable\<T\>）。元素类型 = 枚举器 `Current` 属性类型（:1304，物化实例上已替换）。
- **.coa 读侧泛型闭环**：`ReadGenericClass`（Read.cs:422-565）tpar 限定键注册（:482）→ fn `ret:` 经 `ResolveTypeRef` 解析开放实例化 → `GenericTypeInstantiator.SubstituteMethod`（:128）对返回类型重 Instantiate → Monomorphizer 三捷径（方法开放体 ：189-208 / getter :229-241 / setter :248-252，cod 来源 `definition.Declaration == null` 走 `library.Bodies`）+ `CollectSignatureInstantiations` BFS（:421-478，:470 收集方法返回类型，自动发现 ListEnumerator\<i32\>）+ `BoundTreeSubstituter` 接收者重定位（:224-259，注释原文即 `_list.Count` 场景）。
- **闭包 NRE 线索**：`cocoa build` dotnet 后端 `linkCodDynamically: true`（ProjectBuilder.cs:92）；裸 CLI `Program.cs:284` 走 `Compilation.cs:85` 重载 → **`linkCodDynamically: false`** → stdlib 函数/类内联合并进 app 程序集（CocoaBinder.cs:582-611，`codAssemblies = Empty`）→ TypeDef/MethodDef 行序相对无注入场景整体改变。IlEmitter 类收集两源：局部 `classes`（1a/1b/1c 用，:122-147）vs `program.Classes`（1.5 InterfaceImpl :174 / 2.5 Properties :231 直接迭代）；env 类判定纯名字约定（`__Env_` 前缀，:57-59）；env .ctor 追加到 methods/bodies 平行列表末尾（:158-171/:273-286）；token 映射按 TypeDef 分组序即时重算（MetadataBuilder.cs:248-303）。
- **库化门禁现状**：lambda/函数值——`FindFunctionValueDiagnostic`（Compilation.EmitPipeline.cs:254-266）+ `WriteExpression` 兜底 NotSupportedException（Write.cs:392-393）；delegate 合成类——发射清单阶段过滤（CocoaBinder.cs:543-545，`TypeKind.Delegate` 不进 program.Classes）；事件——后备实例字段被 `IsPureContainerClass` 拒绝（AssemblyReferenceManager.cs:138）→ `IsCodSerializableClass` 失败。fnty **签名** TypeRef 已支持（`fnty{参数,;返回}`，Symbols.cs:359-379），lambda **库体**未接入。
- **FnKey/归一现状**：写侧键 = `库名!head[参数类型…]`（Writer.cs ComputeFnKey :264-275，`ContainingLibrary ?? _moduleName`）；读侧 external 预播种守卫 `ContainsKey` → **先加载者胜**；`ResolveFunction` 缺键回退按"名+元数"归一（Resolve.cs:395-439），多候选非确定；`TypesByName` 按全名索引无库维度；`LoadCodLibraries` 按 `-r` 传入序（AssemblyReferenceManager.cs:30 注释"refcod 拓扑留待完善"，manifest `refcod` 已在 Read.cs:115 解析但未驱动拓扑）。
