## 1. 结论摘要

1. **语言面基本就绪**：类/继承/多接口/虚分派、泛型+约束+单态化、委托/Lambda/闭包/事件、异常处理、switch+when、插值、无符号全集、位运算等均已落地。剩余缺口要么可绕行（元组/record/嵌套类），要么已立项为 6e-M23（out/ref 参数）。
2. **真正的战场在标准库**：编译器本体重度依赖的 `Dictionary<K,V>`（169 处）、`StringBuilder`（Lexer 48 处热点）、**文件 IO（完全缺失）**、SHA256、目录/路径操作，stdlib 目前一概没有。现有 `String.co` 成员面偏教学向且全是 O(n²) 拼接实现。
3. **硬前置是阶段 6 收尾**：stdlib 以 `.cod` 形态注入，而 `List<T>`（及未来的 `Dictionary<K,V>`）是泛型——跨 `.cod` 泛型消费即 G7（C6/C7），当前只能源码方式集成（C8 边界记录明确"待 G7"）。
4. **已定稿的关键决策**：文件 IO 走 Runtime syscall 路线（§4.1）；数字解析 `Parse` 失败抛异常、`TryParse(s, out v)` 依赖 6e-M23（§4.2）；stdlib API 形态总方针为「补齐 C# 形态」（§4.4）；6e-M23 收窄为自举必需核心切片（§4.5）。

## 2. 语言面现状

### 2.1 已具备（直接可用）

| 函数式 | 函数类型 `(A,B)->R` + Func/Action/Predicate 家族、Lambda 提升/方法组转换/闭包捕获、event 多播、delegate 声明糖 |

| 缺口 | C# 编译器中的使用场景 | 绕行方案 |
|------|------|------|
| 元组/解构 §28 🔧 | PE 数据目录 `List<(Entry, uint, uint)>` 等少量值元组 | 私有小类 |
| params/命名/可选参数 §30 🔧 | 少量 | 显式数组实参 / 重载展开 |

### 2.3 必须补的语言件 → 6e-M23（✅ 已落地 2026-08-26）

**out / ref 参数修饰符 + 普通参数可赋值 + 明确赋值分析（对齐 C#）**——已按 [`docs-dev/out与ref参数设计.md`](out与ref参数设计.md) R1-R9 三后端收官；stdlib `Int32.TryParse(s, out v)` 已落地。

- 动机：编译器自身的多返回值助手（CLI 的 `CliHelper.TryTakeValue` 类模式）、stdlib 的 `TryParse(s, out v)` / `TryGetValue(k, out v)` 模式，全部依赖 out 参数。
- 附带修复一个既有偏差：`ParameterSymbol` 构造硬编码 `isReadOnly: true`（ParameterSymbol.cs:6），当前 `function F(x: i32) { x = x + 1 }` 报错——C# 参数本就是可写局部变量，必须一并放宽。
- 完整设计见 [`docs-dev/out与ref参数设计.md`](out与ref参数设计.md)。

**明确不做并对齐确认的项**：

| 项 | 说明 |
|----|------|
| 属性作 out/ref 实参 | 与 C# 一致禁止（非变量），记为对齐项而非缺口 |
| ref local / ref return | 不做；别名仅限参数传递 |
| struct 值类型 | 不做；类替代 |
| 协变逆变 `in`/`out` 型变 | 已有拒绝先例（delegate 型变注解报诊断） |

### 2.4 后置语言件（路线图记录，不阻塞自举）

`out var` 内联声明、`params` 可变参数、命名/可选参数（M23 后续切片）；索引器 `this[i]` + List 属性化（§4.4 方针，Dictionary 落地前完成）；元组、`in` 修饰符、switch 表达式、局部函数（维持 §30/§28/§29 后置状态）。

## 4. 关键设计决策

### 4.1 文件 IO = Runtime syscall 路线（定稿）

新增 syscall 走既有「spec 表 + BuiltinKind 三后端分发」模式（样板：TickCount/UInt64ToString，见 out与ref参数设计.md 附录同款路径表）：

```cocoa
// src\Cocoa.SDK\System.Core\Runtime.co 追加（命名待实现时微调）
syscall function ReadAllText(path: string): string
syscall function WriteAllText(path: string, text: string): void
syscall function ReadAllBytes(path: string): byte[]
syscall function WriteAllBytes(path: string, bytes: byte[]): void
syscall function FileExists(path: string): bool
syscall function FileCopy(src: string, dst: string): void
syscall function DeleteFile(path: string): void
syscall function DirectoryExists(path: string): bool
syscall function CreateDirectory(path: string): void
syscall function EnumerateFiles(dir: string, pattern: string): string[]
syscall function GetCurrentDirectory(): string
syscall function SetCurrentDirectory(path: string): void
syscall function ExecutablePath(): string
syscall function GetEnvironmentVariable(name: string): string   // 未定义返回 ""
syscall function LaunchProcess(path: string, args: string, workdir: string): i32  // 退出码
```

三后端映射：
- **IL**：直通 `System.IO.File.*` / `System.IO.Directory.*` / `System.Environment.*` / `System.Diagnostics.Process`
- **native**：kernel32 导入扩充（运行时导入基建已有）：CreateFileW/ReadFile/SetFilePointer/WriteFile/CloseHandle/DeleteFileW/CopyFileW/CreateDirectoryW/FindFirstFileW/FindNextFileW/GetCurrentDirectoryW/SetCurrentDirectoryW/GetModuleFileNameW/GetEnvironmentVariableW/CreateProcessW/WaitForSingleObject/GetExitCodeProcess
- **Evaluator**：直调对应 BCL

否决案：extern DLL 声明直接调 kernel32——编译器侧改动最小，但 IL 后端映射 DllImport 在非 Windows 托管环境会破，且绕过内建函数分层（跨平台语义失控点）。

### 4.2 数字解析语义（定稿）

- **`Parse`**（ParseInt32/ParseDouble/…）：失败抛异常，用户 try/catch 捕获——对齐 C# `int.Parse` 行为，零语言改动。现有 `Runtime.ParseInt64` 的失败行为随之统一并文档化。
- **`TryParse(s, out v): bool`**：完整 C# 形态，依赖 6e-M23 out 参数；纯 Cocoa 手写字符扫描实现（十进制 v1；f64 含指数解析第二批），**不需要新 syscall**。
- NumberStyles/CultureInfo 参数面明确不做（十进制固定语义记录于语法手册）；十六进制解析作为独立助手（Lexer 自举时用 `Char.IsHexDigit` + 自写循环）。

### 4.3 Dictionary<K,V> 实现要点

- 纯 Cocoa 实现：拉链桶数组 + 容量 ×2 扩容 + `GetHashCode/Equals` 经对象模型路由（M19 已提供基元装箱语义）+ string 键 FNV-1a 快速哈希（避免依赖宿主 GetHashCode 的随机化差异，保证三后端遍历序一致——诊断排序确定性依赖此点）。
- API 先以方法形态落地：`TryGetValue(k, out v)` / `Get(k)` / `Set(k,v)` / `ContainsKey` / `Remove` / `Count()`；**预留索引器语义**（§4.4），提级 `map[k]` 时零返工。
- 前置依赖：G7 跨 `.cod` 泛型消费（否则 stdlib 泛型类只能源码方式集成）。
- 同批：HashSet\<T\>（Dictionary 薄封装）、Stack\<T\>/Queue\<T\>（List 薄封装）。

### 4.4 stdlib API 形态总方针（定稿：补齐 C# 形态）

现有偏差示例：`List<T>.Count()` 是方法不是属性、`list[i]` 不可用（只有 Add/Get/Count）。方针：

1. 新集合类型（Dictionary 等）API 设计时按 C# 形态预留（索引器/属性槽位）；
2. 索引器 `this[i]` 作为语言件提级，排在 M23 之后、自举大量消费 stdlib 之前；
3. 提级窗口内给 List<T> 补 `this[i]` + `Count` 属性（保留旧方法形态兼容期）；
4. 过渡期方法形态合法可用，自举翻译不受阻。

**落地状态（2026-08-29，M0-3）**：`List.co` 已含 `Count`/`Capacity`/`IsReadOnly` 属性与 `this[index]` 索引器（get/set）；Binder 索引器读写已接线（`list[i]` 读经索引器 get、`list[i] = x` 重写为 set_Item 并保栈平衡）；`IndexerSemanticsTests` ×三后端（Evaluator/IL/native x64）锁定 `list[i]` 读/写、`list.Count` 属性、`RemoveAt`（源码方式集成 List，G7 .cod 化待 M0-1c）。

### 4.5 6e-M23 = 自举必需核心切片（定稿）

纳入：`out`/`ref` 参数修饰符、普通参数可赋值（放宽 isReadOnly）、明确赋值分析（对齐 C#）、五处签名身份加修饰符位、`.cod` par 行扩展、三后端、随附验证件（纯 Cocoa `Int32/Int64.TryParse` + `Array.Resize(ref arr, n)`）。
后置：`out var` 内联声明、`params`、命名/可选参数、索引器（见 §4.4）、元组、`in`、switch 表达式、局部函数。
详见 [`docs-dev/out与ref参数设计.md`](out与ref参数设计.md)。

## 5. 编译器结构侧前置

1. **C6/C7（G7-a/b）`.cod` 泛型写读侧关账**：stdlib 以 `.cod` 注入 + 泛型集合跨程序集消费是自举版编译器的运行前提（C8 边界记录："完整 .cod 序列化集成依赖 G7"）。连带 C9 收尾（测试矩阵 + 文档七处同步）。
2. **unchecked 回绕语义锁定 ✅（2026-08-29，M0-2）**：汇编器位打包（x64 36 处/x86 26 处掩码移位）、哈希函数依赖整数回绕与截断转换——native 天然回绕、IL add 不查溢出。新增 `WrapAroundSemanticsTests` ×三后端（Evaluator/IL/native x64）锁定：u32 回绕加/乘、截断矩阵（(u8)300→44 / (u16)70000→4464 / (u64)-1 全 1）、**u32 FNV-1a 对照向量**（""=2166136261 / "a"=3826002220 / "hello"=1335831723 / "Cocoa"=4197378984，与公开向量一致）。**测试即捕获真实缺陷**：IL 后端 `Conv_U2` opcode 误编 `0xD4`（实际 conv.r.un），应 `0xD1`——`i32→u16` 显式截断在 IL 路径恒不生效（70000 而非 4464），Evaluator/native 均已正确；已修正 `IlOpCode.cs`/`IlAssembler.cs` 两处并全量回归（41675 绿）。
3. **翻译约定入档**：ImmutableArray→普通数组/List；ConcurrentDictionary intern→惰性初始化；LINQ→手写循环；record struct→普通类；值元组→私有小类。
