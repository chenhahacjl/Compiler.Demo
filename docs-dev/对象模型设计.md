# Cocoa 对象模型设计 — System.Object 基类 · 全类型成员方法 · System.Type · native vtable

> 状态：🔧 实施中（2026-08-22 立项；**M1/M2/M2b/M2-c/M3/M4 已落地（2026-08-23，全量 29161 测试绿）**，剩 M5 收尾）
> 目标：对齐 C# 对象模型——**每个类型都有成员面**：`1.ToString()` / `1.GetType()` / `"ABC".Substring(0, 2)` / `arr.Sum()` / `s.ToUpper()`；引入编译器内建 `System.Object` 基类（所有类默认继承）+ `System.Type` 类型对象；新增 `long`/`Int64` 基元类型；native 后端补齐**用户类对象模型（真 vtable）**；类 `==`/`!=` 对齐 C# 引用相等。

> 最后更新：2026-08-24

> **落地记录（2026-08-23，M4 native 对象模型）**——与本文 §8 设计的差异点（均已实现并测试锁定）：
> - **PE `.reloc` 节为必要新增**（§8.1 未预见）：DllCharacteristics 含 DYNAMIC_BASE，加载器重定位镜像后
>   vtable 内绝对指针失效 → 按数据绝对 fixup 清单生成基址重定位块（x64 DIR64 / x86 HIGHLOW，页分块 + ABSOLUTE 填充），
>   有重定位时不声明 RelocsStripped。此修复同时是后续任何"数据段存代码地址"特性的前置。
> - **vtable 头部自引用替代 typeId**：[0] 一律写自身地址（typeId 无消费方），使 Type 值与对象共用
>   `[[x]+8]` 取名公式——否则用户类 vtable 作 Type 值调用 ToString 会把 typeId 当指针解引用。
> - **Object 面四个运行时函数为栈 ABI**：槽内容可能是用户 override（用户函数栈 ABI），callreg 无法区分 ABI，
>   故 ObjectToString/ObjectGetHashCode/ObjectGetType/ObjectEquals 以 BeginStackFunction 发射
>   （InitParam 读参），全部旧 SetArg 调用点迁移至 EmitStackRuntimeCall。
> - **System.Type 接收者不走槽分派**：Type 值的 ToString/GetHashCode/Equals 直调运行时默认（读名字字段/
>   指针比较），因槽 0..2 可能装着期望对象 this 的用户 override；Name/FullName 仍走 [vt+8] 内联。
> - **静态字段支持零值存储**（§8.6 之外补充）：`$sf:` 数据槽 + Load/Store；含初始化器的静态构造
>   （.cctor 符号存在即视为有初始化语义）在门禁明确拒绝（native 无触发时机），空声明合法。
> - **接口声明 native 明确拒绝**（接口分派未实现）；any/数组/枚举接收者的 Object 成员调用由
>   NativeObjectFaceValidator 报错（替代原 M4 占位守卫，文件已删除）。
> - 类方法 IrFunction 名 mangle 为 `Namespace.Class.Name$参数类型`（平坦命名空间防撞）；入口函数保持裸名。
> - 可达性升级为函数+存活类双队列闭包：new 标记类存活 → 连带基类链/实例 ctor/虚根实现
>   （新根登记时对既有存活类补扫），抽象类不可 new 故不发 vtable。

> **落地记录（2026-08-23，M2-c + M3）**——与本文设计的差异点（均已实现并测试锁定）：
> - SystemObject 成员面为**编译器内建符号**（`SystemObjectMembers.Ensure()` 幂等注入，非 stdlib facade 源码）——虚方法语义与 facade 静态降级互斥；新 BuiltinKind：ObjectToString/ObjectGetHashCode/ObjectEquals/ObjectGetType/ObjectStaticEquals/ObjectReferenceEquals/TypeName/TypeFullName

> - override 校验升级**签名匹配**（参数个数/类型逐一 + 返回类型相同，CS0115/CS1715 式诊断）；HasExplicitBase → HasBaseClass 反转
> - 类间转换方向根修：Conversion.Classify 原「基类→派生隐式 / 派生→基类显式」与注释相反的既有缺陷已修正，IL 补 castclass 下转发射
> - `==` 引用相等：Bind 动态合成 ReferenceEquals/ReferenceNotEquals kind（双侧类类型且有继承关系）；any/string/值类型维持现状（any 统一留 M5）
> - **net9 CoreLib 的 System.Type 无 get_Name**：Type.Name 经 FullName.Substring(LastIndexOf('.')+1) 组合发射（无点回退全名），Evaluator 同构切分，三后端一致
> - Evaluator OOP：`EvaluatorObject{Class, Fields[]}` 自管表示（运行时链虚分派镜像 CLR 槽复用）、this 接收者栈、静态字段槽 + .cctor 惰性触发、字段零值默认、用户类 GetType 返回 EvaluatorTypeInfo（FullName 承载）
> - native 守卫：NativeObjectFaceValidator 对 Object 成员面调用报明确"未实现"诊断（M4 落地后移除）
> - `.cod`：内建单例发 systype 符号防读侧造重复类；Object 内建方法随引用序列化且读侧复用单例；.cod 类读侧补默认 BaseType=SystemObject

## 1. 目标与范围

Cocoa 语言对齐 C# 的对象模型与类型成员体验：

- **`System.Object` 基类**：所有类未显式声明基类时默认继承它；提供公共方法 `ToString()` / `GetHashCode()` / `Equals(any)` / `GetType()`（实例虚方法）+ `Equals(any, any)` / `ReferenceEquals(any, any)`（静态）。
- **全类型成员方法**：基元类型（`int`/`long`/`double`/`bool`/`char`/`byte`）与 `string`/`T[]` 都以 C# 风格提供实例方法——`1.ToString()`、`1.GetType()`、`"ABC".Substring(0, 2)`、`s.ToUpper()`、`arr.Sum()`、`arr.Sort()`。
- **`System.Type` 类型对象**：`GetType()` 返回 `System.Type`（native 上即 vtable 记录），含 `Name`/`FullName`/`ToString()` 等。
- **`long`/`Int64`**：新增 64 位整型基元类型全链路（词法 → 绑定 → Evaluator/IL/native）。
- **native 对象模型**：native 后端从"编译期拒绝实例类"演进为**用户类完整对象模型**（对象布局 + 真 vtable 虚分派 + 实例方法 `this`）。
- **`==`/`!=` 对齐 C#**：类类型引用相等，值类型/`string` 值比较。

**边界**：`.cod` 库 OOP（`requires:dotnet` 判定）与"用户 `.cod` 库引用系统标准库"不在本次范围；`System.Type` 的 `Type.GetType(string)` 运行时按名查类型不做。

## 2. 核心设计决策

| 决策 | 内容 |
|------|------|
| `System.Object`/`System.Type`/基元封装类 = **编译器内建特殊类符号**（singleton） | 非 stdlib `.cod` 类、**不被发射为 TypeDef**。原因：`.cod` 类反序列化后 `IsExternal=false`，用户程序会把 stdlib 类发成 TypeDef，与 mscorlib `System.Object`/`System.String` 撞名。IL 映射框架 TypeRef，native 映射运行时 vtable |
| 基元类型挂"类封装" | `int→Int32`、`long→Int64`、`string→String`、`double→Double`、`bool→Boolean`、`char→Char`、`byte→Byte`（编译器内建，IL 走框架 TypeRef）；`TypeSymbol` 加 `ClassSymbol` 关联 |
| Object 方法走 **BuiltinKind 分发** | 复用功能层机制（`标准库设计.md` §11）：三后端 `switch`，Evaluator C# / IL mscorlib / native 运行时函数 |
| **基元/数组实例方法两条路由** | **A 路由**（编译器内建 BuiltinKind）：基元的 Object 方法 + `CompareTo`/`Parse`/`MaxValue`/`MinValue`/格式化 `ToString(format)` 等。**B 路由**（stdlib 实例方法源码，降级为静态）：`string`/`T[]` 成员在 `System.String`/`System.Array` 中写为实例方法（`this`），编译器把实例方法降级为静态（receiver 前置首参、`this` → 隐藏首参），三后端零改动、Cocoa 实现保留、native 可用 |
| **仅实例语法** | 删除静态入口 `String.ToUpper(s)`/`Array.Sum(a)` 等，stdlib 重写为实例方法源码；`System.Console`/`System.Math`/`System.Runtime` 非值类型成员面，保持静态调用 |
| `System.Type` native 表示 | **vtable 记录即 Type 对象**（typeId + 名字指针 + 方法槽），`GetType()` 返回对象 vtable 指针，`Type.Name`/`Type.ToString()` 读名字字段 |
| native 虚分派 = **真 vtable** | 对象头存 vtable 指针；vtable 数据段记录含方法槽（数据段→代码段绝对地址重定位）；`call reg` 间接调用 |
| `==`/`!=` | 类类型 → 引用相等（新 binary op kind）；值类型/`string` → 值比较 |

## 3. System.Object 基类

### 3.1 语义

- `ClassTypeSymbol` 无显式基类 → `BaseType = SystemObject`（`DeclareClassGroup` 落位）。
- 成员解析沿继承链自然上溯到 Object（`ClassTypeSymbol.GetMethod/GetMethods/GetProperty` 循环条件 `current != null` 已支持）。
- 显式 `class C: Object` / `class C: System.Object` 解析到内建 singleton，合法。

### 3.2 成员（C# System.Object 对齐）

| 成员 | 签名 | 类别 | 默认实现 |
|------|------|------|---------|
| `ToString` | `(): string` | 实例虚 | IL/Evaluator：`object.ToString()`；native：运行时 `ObjectToString`（读 vtable 名字） |
| `GetHashCode` | `(): int` | 实例虚 | IL/Evaluator：CLR 默认；native：运行时 `ObjectGetHashCode`（指针散列） |
| `Equals` | `(any): bool` | 实例虚 | IL/Evaluator：`object.Equals`；native：指针引用相等 |
| `GetType` | `(): System.Type` | 实例非虚 | 返回对象 vtable 指针（native）/ CLR `Type`（IL/Evaluator） |
| `Equals`（静态） | `(any, any): bool` | 静态 | 引用相等 |
| `ReferenceEquals` | `(any, any): bool` | 静态 | 引用相等（native 复用 `ObjectEquals`） |

用户类 `override ToString()` / `GetHashCode()` / `Equals()` 校验基类链含 Object 同名虚方法（`FunctionSymbol.OverriddenMethod` 指向 Object 方法），override 生效。

## 4. 全类型成员面（实例方法）

### 4.1 `object` — System.Object

`ToString()` / `GetHashCode()` / `Equals(any)` / `GetType()`；静态 `Equals(any, any)` / `ReferenceEquals(any, any)`。

### 4.2 `int` — System.Int32（A 路由）

- 实例：`ToString()`、`ToString(format: string)`、`GetHashCode()`、`Equals(int)`、`GetType()`、`CompareTo(int): int`
- 静态：`Parse(string): int`、`MaxValue` / `MinValue`（常量）
- 格式化：`D`/`d`、`X`/`x`（对齐现有插值 `{x:X2}` 已支持）

### 4.3 `long` — System.Int64（A 路由）

同 `int` 全套（`Int64ToString`/`ParseInt64` native 新增）。

### 4.4 `string` — System.String（B 路由，stdlib 重写为实例方法）

| 成员 | 备注 |
|------|------|
| `Length`（属性） | 已有 |
| `s[i]: char`（索引器） | 已有 |
| `Substring(start)` / `Substring(start, length)` | 现有 `substring` 归一为此名 |
| `ToUpper()` / `ToLower()` | 现有实现 |
| `StartsWith(s)` / `EndsWith(s)` / `Contains(s)` | 现有 |
| `IndexOf(string)` / `IndexOf(char)` | 补 char 重载 |
| `Replace(old, new)` | 现有 |
| `Trim()` / `TrimStart()` / `TrimEnd()` | 补 TrimStart/TrimEnd |
| `Split(char): string[]` | 现有 |
| `PadLeft(width)` / `PadLeft(width, char)` / `PadRight(...)` | 补单参重载 |
| `ToString()` / `GetHashCode()` / `Equals(string)` / `GetType()` | Object 成员 |
| 静态 `IsNullOrEmpty(string): bool` | 补 |
| 非 C# 但保留（兼容现有）：`Reverse()`、`Replicate(int)`、`CountChar(char)`、`IsPalindrome()`、`CountSubstring(string)` | 现有 stdlib 函数 |

### 4.5 `T[]` — System.Array（B 路由，stdlib 重写为实例方法）

`Length`（属性，已有）；`Sum()` / `Min()` / `Max()` / `Average()` / `Contains(v)` / `IndexOf(v)` / `Reverse()` / `Sort()`（`int[]`/`double[]` 重载，现有实现）；`ToString()` / `GetHashCode()` / `Equals(any)` / `GetType()`（Object，`ToString` 返回类型名）。C# 的 `Array.Sort` 是静态且原地排序；本语言按现有"返回新数组"语义做实例方法。

### 4.6 `double` — System.Double（A 路由）

`ToString()`、`ToString(format)`（`F`/`E`/`G`/plain，对齐现有插值格式）、`GetHashCode()`、`Equals(double)`、`GetType()`、`CompareTo(double)`；静态 `Parse(string)`、`MaxValue` / `MinValue` / `Epsilon` / `NaN` / `PositiveInfinity` / `NegativeInfinity`、`IsNaN(double)` / `IsInfinity` / `IsPositiveInfinity` / `IsNegativeInfinity` / `IsFinite` / `IsInteger`。

### 4.7 `bool` — System.Boolean（A 路由）

`ToString()`（"True"/"False"）、`GetHashCode()`、`Equals(bool)`、`GetType()`；静态 `Parse(string)`、`TrueString` / `FalseString`。

### 4.8 `char` — System.Char（A 路由）

`ToString()`、`GetHashCode()`、`Equals(char)`、`GetType()`；静态 `IsDigit(char)` / `IsLetter(char)` / `IsWhiteSpace(char)`、`ToUpper(char)` / `ToLower(char)`、`Parse(string)`、`MaxValue` / `MinValue`。

### 4.9 `byte` — System.Byte（A 路由）

`ToString()`、`GetHashCode()`、`Equals(byte)`、`GetType()`、`CompareTo(byte)`；静态 `Parse(string)`、`MaxValue` / `MinValue`。

### 4.10 `System.Type`（A 路由，native 上 vtable 即 Type 对象）

`Name`（属性）、`FullName`（属性）、`ToString()`、`Equals`、`GetHashCode`、`GetType`。

### 4.11 静态容器类（非值类型成员面，保持静态）

`System.Console` / `System.Math` / `System.Runtime` 保持静态调用（`Console.WriteLine`、`Math.Sqrt`、`Runtime.*`）——它们不是某值类型的成员。

## 5. 成员面路由：A 路由（编译器内建）与 B 路由（stdlib 实例方法源码）

> **架构决策变更（2026-08-23，全面 facade）**：原 A/B 双路由合并为**单一 facade 模式**，彻底对齐 C#——
> 基元/string 的成员面载体是 stdlib 源码里的真实类（`System.Int32`/`System.String`/...），实例方法
> 声明被编译期降级为静态（隐藏首参 `this: T`），三后端按普通静态容器调用发射，零特判。
>
> - facade 标记不序列化：注入侧按全名映射表补齐；声明侧在成员绑定前标记（时序敏感）
> - `this` 在降级方法体内解析为隐藏首参变量（`BindThisExpression` 特判）
> - 底层依赖运行时能力的成员走 syscall 原语（`Int32ToString`/`DoubleToString` 等，BuiltinKind 分发）
> - 已落地：Int32/Int64/Double/Boolean/Char/Byte 六类型 ToString 全链路（双后端 e2e 一致）
> - **Array 保留静态容器**：非泛型无法声明"任意数组"接收者，实例化待 6e-M20 泛型
> - 待铺开：String 实例化重写（静态签名兼容——降级后首参形态不变）、Object/Type facade（虚方法语义随 M2-c/M3/M4）
> - 原 A 路由 BuiltinKind 表仅保留功能层原语与上述 ToString 系 syscall

### 5.1 为什么不能做"真实实例方法"（关键约束）

`string` 值映射到 **mscorlib 的 `System.String`**（TypeRef）；stdlib 的 `System.String` 是独立 TypeDef 静态类（`.cod` 反序列化 `IsExternal=false`）。若在 stdlib `System.String` 上声明真实实例方法，`this` 类型会是"用户程序里的 System.String"（TypeDef），与运行时实际的 mscorlib 字符串（TypeRef）不匹配 → IL 验证拒绝。

反之，把基元实例调用直接映射到 mscorlib 实例方法会在 **native 后端失效**（native 无法调 mscorlib；stdlib 的 Cocoa 实现天然三后端通用）。

→ 结论：**基元/数组实例方法 = 编译期降级**：

| 路由 | 机制 | 覆盖 | 后端 |
|------|------|------|------|
| **A 编译器内建（BuiltinKind）** | 基元 Object 方法 + CompareTo/Parse/MaxValue/MinValue/格式化 | `int.ToString()`、`42.GetHashCode()` | IL → mscorlib `callvirt`；Evaluator → CLR；native → 运行时函数（`IntToString` 等） |
| **B 扩展方法式降级** | 实例方法声明降级为静态（`this` → 隐藏首参）；实例调用 `receiver.Method(args)` → 静态 `System.String.Method(receiver, args)` | `s.ToUpper()`、`a.Sum()`、`arr.Sort()` | 三后端零改动（现有静态容器类调用路径） |

### 5.2 B 路由的 stdlib 源码形态（重写后）

```cocoa
// System.String —— 实例方法源码（编译器降级为静态：this → 隐藏首参）
namespace System
{
    class String
    {
        function ToUpper(): string
        {
            var result = ""
            var i = 0
            while i < this.Length
            {
                var v = int(this[i])
                if v >= 97 && v <= 122 { result = result + string(char(v - 32)) }
                else { result = result + string(this[i]) }
                i = i + 1
            }
            return result
        }

        function Substring(start: int, length: int): string
        {
            return this.substring(start, length)
        }
    }
}
```

`"abc".ToUpper()` → 绑定 `System.String.ToUpper`（实例）→ 降级为静态 `ToUpper(string)` → 三后端按静态容器类方法发射。

### 5.3 绑定解析顺序（`BindMemberCallExpression`，Binder.cs 扩展）

对基元/数组 receiver：

1. **特殊内建**：`string.substring` / `.Length` / `s[i]`（现有，保留）。
2. **Object 内建方法**（A 路由）：`ToString` / `GetHashCode` / `Equals` / `GetType` → `BuiltinKind`。
3. **实例方法降级**（B 路由）：查 receiver 类型映射的静态容器类（`string→System.String`、`T[]→System.Array`）的同名方法，首参类型可接收 receiver（identity 或隐式转换），用现有 `ResolveMemberOverload` 重载解析，receiver 前置为首参。

用户类 receiver 不受影响（既有 `GetMethod` 实例路径）。

## 8. native 对象模型（真 vtable）

### 8.1 汇编器数据重定位基础设施（vtable 前置）

当前能力核实：
- 代码→数据用 RIP-relative（`_dataFixups` 在 `Patch` 写 `dataTextDelta + dataOffset - (P+4)`）；**数据→代码/数据→数据绝对指针尚不存在**。
- PE 布局：`TextRva=0x1000`、`dataRva = Align(TextRva + codeLen, 0x1000)`、`imageBase` = 0x400000(x86)/0x140000000(x64)。`Patch` 已收 `dataTextDelta` + `imageBase`。
- IR 已有 `CallReg <dst> <reg>`（间接 `call reg`）；栈 ABI `ReserveArgs`/`StoreArg`/`FreeArgs` 可用。

新增：
- `IAssembler`（X64/X86 对称）：数据重定位注册 + `Patch` 内解析——
  - `AddDataCodeFixup(dataOffset, label)` → Patch 写 `imageBase + TextRva + labelOffset`（绝对代码地址）。
  - `AddDataDataFixup(dataOffset, symbol)` → Patch 写 `imageBase + (dataTextDelta + TextRva) + dataOffset`（绝对数据地址）。
- `IrToAssembler`：EmitFunctions 之后新增 `RegisterDataFixups()` 通道（`_nameToLabel`/`_dataSymbols` 已就绪）。
- `IrProgram`/`IrDataItem`：新增 vtable 数据项（typeId + 名字 data-key + 函数名槽数组）。

### 8.2 对象布局

```
[0]  vtablePtr (4/8B)      —— 指向该具体类的 vtable 记录
[4]  pad (4B)              —— 8 字节对齐头（对齐 string/array 惯例）
[8]  field0 …
[8+…] field1 …             —— 基类字段在前、派生字段在后；double/long 字段 8 字节对齐
```

实例尺寸 = 8 + Σ(对齐字段)。`new Foo(...)` = `Alloc(size)` → store vtable → `call` 构造（this + args）。

### 8.3 vtable 记录（数据段，每具体类一条；即 System.Type 对象）

```
[0]  typeId:int           —— 编译器分配；基元/Type 固定 id
[4]  pad
[8]  namePtr              —— 数据重定位 → 内建类型全名字符串
[8+ps]  槽 0..3           —— Object 固定：ToString=0, GetHashCode=1, Equals=2, GetType=3
[8+4·ps] 用户虚方法槽       —— 继承链 base→derived 追加；override 复用槽位
```

**槽分配算法**：`CollectVirtualSlots(ClassTypeSymbol)`——Object 4 槽固定，沿继承链对每个声明的虚方法按签名去重分配递增索引；每类 vtable 逐槽填"沿继承链最近的实现"（含运行时函数名，如 `ObjectToString`/`ObjectGetHashCode`/`ObjectEquals`）。抽象类贡献槽位但不可实例化（vtable 仅具体类使用）。

### 8.4 实例方法 ABI 与命名

- `this` 为隐藏 arg0（栈 ABI）：`CreateParameters` 前置 `this`；`ParamByteOffset`/`ParamsTotalBytes` 计入；`BoundThisExpression` 映射该寄存器。
- **IrFunction 命名须全局唯一**（`function.EmitName` 对实例方法只是裸名会撞）：实例方法用 `ClassFullName.MethodName[+参数后缀]`，`_nameToLabel` 不冲突。

### 8.5 虚分派

```asm
mov  vtable = [obj + 0]
mov  fn     = [vtable + 8 + 4·ps + slot·ps]
ReserveArgs / StoreArg(this, args) / CallReg fn / FreeArgs
```

非虚实例方法直调；`base.Method()` 直调基类实现（非虚）。基元 Object 方法编译期静态分派（`int`/`string` 等 sealed，无 vtable）。

### 8.6 新增发射（现 `default: throw` 的节点）

`ObjectCreationExpression`（Alloc + store vtable + call ctor）、`MemberAccessExpression`（字段读 `Load [obj+off]`）、`MemberAssignmentExpression`（`Store`）、`ConstructorChainExpression`（构造链 + 字段初始化器）、`ThisExpression`、`BaseExpression`。

### 8.7 可达性

`ComputeReachableFunctions` 新增"存活类"计算（`new` 可达 → 类 + 全部基类 + Object）；可达集纳入存活类的 .ctor/虚槽实现/方法体；stdlib 未用类不发 vtable（防数据膨胀）。

### 8.8 Object 方法 native 化

| 方法 | 基元（静态分派） | 用户类（虚槽默认） |
|------|-----------------|-------------------|
| `ToString()` | `IntToString`/`Int64ToString`/`DoubleToString`/`CharToString`/bool 串 | 运行时 `ObjectToString`（读名字） |
| `GetHashCode()` | 运行时 `ObjectGetHashCode`（按值） | 运行时 `ObjectGetHashCode`（指针散列） |
| `Equals(any)` | 数值 `Cmp`/`StrEquals`/指针 `ObjectEquals` | 运行时 `ObjectEquals`（引用相等） |
| `ReferenceEquals` | `ObjectEquals`（指针比较） | — |
| `GetType()` | 对应封装类 vtable（`LeaData`） | 返回 `[obj+0]`（`TypeOf`） |

### 8.9 Compilation.EmitNative

`IsPureContainerClass` 拦截（`Compilation.cs:262`）改为"容器类或对象模型类"放行；`.cod requires` 校验语义保持不变。

## 10. Evaluator 的 this 传递与 OOP 缺口

Evaluator 目前对 OOP 节点 `ObjectCreationExpression`/`ThisExpression`/`BaseExpression`/`ConstructorChainExpression`/`MemberAssignmentExpression` 走 `default: throw`。本次补齐：

- `ObjectCreationExpression`：构造 CLR 实例 + 构造链 + 字段初始化器。
- `ThisExpression`/`BaseExpression`/`ConstructorChainExpression`/`MemberAssignmentExpression`（类字段写）。
- **`this` 传递**：`EvaluateCallExpression` 对实例方法把 target 注入隐藏 `this` 局部（`BoundThisExpression` 求值返回它）；`EvaluateMemberCallExpression` 不再丢 target（当前直接把 `node.Method` 包成 `BoundCallExpression` 丢 target）。
- Object 方法直接 CLR 语义；`==`/`!=` 类 → `ReferenceEquals`。

## 13. 验收标准

- `1.ToString()` / `1.GetType()` / `"ABC".Substring(0, 2)` / `"ab".ToUpper()` / `arr.Sum()` / `arr.Sort()` 在 Evaluator / IL / native x86/x64 四路一致。
- 隐式继承：无基类类 → `BaseType = SystemObject`；显式 `class C: Object` 合法。
- override：用户类 `override ToString()`/`GetHashCode()`/`Equals()` 生效（三后端）。
- `System.Type`：`GetType()` 返回 Type，`Name`/`FullName`/`ToString()` 三后端一致。
- `long` 全链路（字面量/转换/运算/数组/打印/Parse）四路一致 + 越界/截断诊断。
- native 用户类 e2e：`new`/继承/多态（vtable 分派）/字段/构造链/`base.Method()`/GetType/Type.Name。
- `==`/`!=`：类引用相等、值类型/string 值比较四路一致。
- REPL（Evaluator）：类实例化 + 实例方法（含 `this`）可用。
- 全量测试回归通过；文档（`OOP设计.md`/`标准库设计.md`/`类库设计.md`/`语法手册.md`/`开发计划.md`）同步。
