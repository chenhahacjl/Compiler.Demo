# 文档注释设计（6e-M24 规划）

> 状态：📋 设计定稿（2026-08-26 定稿；**开发延后**，未开工）
> 目标：为 Cocoa 增加 **`///` 文档注释**语言特性，编译期产出 **.NET 兼容 XML 文档文件**（对齐 C# `GenerateDocumentationFile` 行为）并把文档 **内嵌 `.cod` 程序集**，使 stdlib / 库互操作的文档可随程序集分发，为 REPL 与未来 Cocoa.IDE 的悬停提示打地基。
> 核心决策：① v1 只做 `///` 单行形式（`/** */` 块形式后置）；② 标签集取 C# 兼容最小子集 `<summary>/<param>/<returns>/<remarks>`，未知标签宽容保留不报错；③ XML member name 采用 **.NET DocID 风格**（`T:/M:/F:/P:/E:` + 全名类型拼写），直接复用 .NET 生态解析器；④ XML 文件与 `.cod` 内嵌双通道——XML 给人/外部工具，`.cod` 内嵌给编译器/REPL/IDE；⑤ 生成由开关控制（CLI `--doc` + coproj `[options] doc=`），**默认关闭**。
> 相关文档：`docs-dev/Cocoa.IDE设计.md`（SemanticModel 门面消费方）、`docs/项目格式规范.md` §.cod 段格式、`docs-dev/out与ref参数设计.md` §7（cod 格式扩展先例）、`docs/编译手册.md` §3（构建选项挂点）
> 最后更新：2026-08-26

## 1. 目标与范围

### 1.1 纳入本里程碑（核心切片）

| 项 | 说明 |
|----|------|
| `///` 文档注释词法 | 新 Trivia Kind `SingleLineDocCommentTrivia`；双方言（`.co`/`.cs`）拼写一致 |
| 提取模型 | `DocCommentExtractor`：leading trivia → 结构化文档（summary/params/returns/remarks） |
| 符号挂点 | `Symbol.DocumentationText`：Binder 创建符号处惰性回填；`.cod` 反序列化侧按 DocID 回填 |
| XML 文档文件 | 编译产物旁同名 `.xml`，格式完全兼容 .NET doc file（§5） |
| 生成开关 | CLI `--doc` + coproj `[options] doc = true/false`，默认关（exe/library/cod 三产物均生效） |
| `.cod` 内嵌段 | `(docs …)` 段：DocID → 规范化文本字典；Version 保持 1，读侧拒旧重建（先例见 out/ref par 行扩展） |
| REPL 消费 | `ls` 附带 summary 首行；`#docs <符号>` 元命令查看完整文档 |
| stdlib 覆盖 | System.Core 17 文件 + Collections 2 文件常用 API 分批补注 |

### 1.2 后置（不在本里程碑）

`/** */` 块文档形式；`<exception cref>` / `<see cref>` 的 cref 符号解析（v1 当纯文本保留）；`<inheritdoc>` 继承文档合并；IDE 悬停 UI 本体（属 Cocoa.IDE M 系列）；XML 转 CHM/Site 等下游工具链。

### 1.3 动机

- **自举**：阶段 7 用 Cocoa 重写编译器时，库 API 自描述是团队协作硬需求；
- **互操作**：stdlib 以 `.cod` 分发、无源码语法树，文档必须随程序集走才能被消费方看到；
- **生态对齐**：XML 格式与 .NET 一致后，Sandcastle/DocFX 等 .NET 工具链可直接消费 Cocoa 库的文档文件。

## 2. 现状盘点

### 2.1 Trivia 机制（词法已就绪一半）

- 注释已是 trivia：`//` → `SingleLineCommentTrivia`、`/*…*/` → `MultiLineCommentTrivia`（`Lexer.ReadTrivia` 分派于 `'/'` 分支，Lexer.cs:103-118；读取实现 :213-280）。trivia 种类枚举在 SyntaxKind.cs:10-15，`SyntaxFacts.IsComment` 判定于 SyntaxFacts.cs:77。
- trivia 不进语法树 `GetChildren()`：以不可变数组挂在 token 上（`SyntaxToken.LeadingTrivia/TrailingTrivia`，SyntaxToken.cs:29-30）；`SyntaxTrivia` 是独立小类（Kind/Position/Text），非 SyntaxNode。全量遍历只能走树到 token 读两侧（`PrettyPrint` 即如此）。
- 词法主流程：`Lex()` 先收 leading trivia → 读 token → 收 trailing trivia（Lexer.cs:57-82）；trailing 遇换行即停（:120-130）。
- ⚠️ 共存注意：`ParserCore` 构造器把 BadToken 文本转成 `SkippedTextTrivia` 重插到后继 token 的 leading（Parser.cs:47-72）——doc trivia 需在该重插逻辑中保持相对顺序。

### 2.2 声明节点与符号挂点

- 所有声明均为 `MemberSyntax` 派生（带 Modifiers）：顶层 function/class/interface/enum/delegate/namespace/import/using，类成员 constructor/property/event/field/externMetadata。分派入口 `Parser.ParseMember()`（Parser.cs:195）、类内 `ParseClassMember()`（:820）。
- 符号保留声明引用：`FunctionSymbol.Declaration`（FunctionSymbol.cs:30）、`ClassTypeSymbol` 构造收 declaration（ClassTypeSymbol.cs:62-68）等——这是"从声明 LeadingTrivia 惰性提取文档"的天然挂点。
- Binder 符号创建点（提取插入位）：顶层函数 Binder.cs:845、类方法 :2810、构造 :1441、接口方法 :2200、属性访问器 :2253/:2483、合成 .cctor :1424。
- **关键约束**：`.cod` 外部符号（stdlib）反序列化时 `Declaration = null`（CodSerializer.cs:1857 一带）——其文档无法依赖语法树，必须走序列化通道（§6）。

### 2.3 `.cod` 序列化管线

- `.cod` 为文本 s-表达式格式：`(cod "COCOD" <ver>)` 根，段依次 `symbols` / `bodies` / `manifest`，末行 `(checksum sha256:<hex>)` 覆盖全文件（CodSerializer.cs:29-156）。
- Version 字段存在但恒为 1；演进策略=读侧拒旧+重建库（版本不符抛异常，CodSerializer.cs:1463-1467；out/ref 扩展即此先例）。
- 内存模型 `CodProgram`（CodProgram.cs:10-79）：Functions/Globals/Enums/Classes/Bodies/Requires/…/Namespaces——新增 Docs 字典即可。
- 写文件点：`Compilation.EmitCocoa` 构造 CodProgram 后落盘（Compilation.cs:483-504）。

### 2.4 其他基建

| 基建 | 现状 | 对本特性的意义 |
|------|------|----------------|
| 诊断 | 无数字 ID 体系；`DiagnosticBag` 具名 Report 方法（警告先例 `ReportFacadeMarkerRecommended` :144 等，新方法追加文件尾部） | 新增 `ReportMalformedDocComment` 零成本 |
| REPL 元命令 | `[MetaCommand]` 特性 + 反射自动注册（Repl.cs:22-40）；已有 ls/dump/load 等（CocoaRepl.cs:75-142） | `#docs` 直接加一个特性方法 |
| stdlib | 源码 `src\Cocoa.SDK\`（System.Core 17 文件 + Collections 2 文件）；`tools\build-sdk.cmd` 构建 → 产物收集到 `src\Cocoa.Cs\libs\`（README 所述 build-stdlib 已更名） | §8 覆盖计划的对象 |
| 测试基建 | `AssertingEnumerator` 不遍历 trivia（AssertingEnumerator.cs:31-46）；LexerTests 有 trivia 矩阵（GetSeparators :444-453、SlashToken 相邻特判 :714-719）；诊断 span 用 AnnotatedText；cod 往返 CodSerializerTests | §10 测试落位依据 |

## 3. 语法规范

### 3.1 形式

v1 仅单行文档注释：行内 `///` 起（含缩进前缀）至换行止。双方言拼写完全一致：

```coco
/// <summary>计算两数之和。</summary>
/// <param name="a">第一个加数。</param>
/// <param name="b">第二个加数。</param>
/// <returns>两数之和。</returns>
fn Add(a: int, b: int) -> int
{
    return a + b
}
```

```csharp
/// <summary>计算两数之和。</summary>
int Add(int a, int b)
{
    return a + b;
}
```

### 3.2 词法规则

| 规则 | 内容 |
|------|------|
| 识别优先级 | Lexer trivia `'/'` 分支中 `///` 优先于 `//` 识别（前缀匹配） |
| Kind | 新增 `SingleLineDocCommentTrivia`；`SyntaxFacts.IsTrivia` 同步纳入 |
| Text 内容 | 保留 `///` 之后原始文本（含首空格由提取器统一剥离一层） |
| 归属 | 作为 leading trivia 附着到其后第一个 token；连续多个 doc 行构成一个逻辑文档块 |
| 断块条件 | 文档块与声明之间允许空白/换行 trivia；遇到任何非 doc 非空白 trivia 或普通代码即断开，其后 `///` 归属下一个声明 |
| `////` 及更多斜杠 | 视为普通单行注释（对齐 C#：四个及以上斜杠不是文档注释） |
| 未闭合标签 | 词法层不管（doc 行总是自然终止于换行）；格式校验在提取层做（§4.3） |

### 3.3 标签集

| 标签 | 出现次数 | 说明 |
|------|----------|------|
| `<summary>` | ≤1 | 摘要；REPL/悬停显示其首行 |
| `<param name="x">` | 0..n | 参数文档，name 对应形参名 |
| `<returns>` | ≤1 | 返回值说明 |
| `<remarks>` | ≤1 | 补充说明 |

- 未知标签（如 `<example>`）：**宽容保留**为原始文本，不报错、不丢失——保证向前兼容 C# 风格注释。
- 标签跨行内容合法：`<summary>` 正文可延续到后续 `///` 行直到闭合标签。

### 3.4 后置形式

`/** … */` 块文档注释（对应 `MultiLineDocCommentTrivia` 变体）留待后续里程碑；本设计的提取模型与两条输出通道对其无假设，届时仅扩展词法与提取器入口。

## 4. 提取模型与符号挂点

### 4.1 结构化模型

```
DocComment
├── RawText        // 规范化原始文本（多行合并 + 剥每行 /// 前缀，保留标签）
├── Summary        // string?（<summary> 内文）
├── Params         // ImmutableDictionary<string, string>（name → 内文）
├── Returns        // string?
└── Remarks        // string?
```

`DocCommentExtractor.Extract(ImmutableArray<SyntaxTrivia> leading)` 为唯一入口：扫描 leading 中的连续 doc trivia 块，合并、剥前缀、浅解析标签。纯函数、无副作用，供 Binder 与发射层共用。

### 4.2 符号挂点

- `Symbol` 基类新增 `string? DocumentationText`（存规范化原文；结构化字段按需再解析，避免符号常驻开销）。
- 回填时机：
  - **同程序集**：Binder 各符号创建点从 `Declaration.LeadingTrivia` 提取一次缓存（顶层函数/类方法/构造/接口方法/属性访问器/字段/枚举成员/event/delegate）。
  - **跨程序集**：`.cod` 反序列化创建符号时按 DocID 从 `CodProgram.Docs` 查表回填（§6.3）。
  - 合成符号（如 .cctor）：DocumentationText = null，不生成文档条目。

### 4.3 诊断（全部警告级）

| 诊断 | 触发 | 时机 |
|------|------|------|
| 报告文档注释格式错误 | 标签未闭合、`<param>` 缺 name 属性 | 提取时（Parser 诊断流，经 SyntaxTree.Diagnostics 合并） |
| （可选增强）参数名不存在 | `<param name="x">` 的 x 不在该声明的形参列表 | Binder 校验（需符号参数面，放 M2 可选项） |

登记方式遵循仓库惯例：`DiagnosticBag` 尾部追加具名方法，无 ID 注册表。

## 5. XML 文档文件规范

### 5.1 文件布局（与 .NET 完全兼容）

```xml
<?xml version="1.0"?>
<doc>
    <assembly>
        <name>MathLib</name>
    </assembly>
    <members>
        <member name="T:MathLib.Calc">
            <summary>简易计算器。</summary>
        </member>
        <member name="M:MathLib.Calc.Add(System.Int32,System.Int32)">
            <summary>计算两数之和。</summary>
            <param name="a">第一个加数。</param>
            <param name="b">第二个加数。</param>
            <returns>两数之和。</returns>
        </member>
    </members>
</doc>
```

- 文件名：产物基名 + `.xml`（`Calc.cod → Calc.cod.xml`？否——对齐 .NET 习惯用**程序集名**：`MathLib.dll → MathLib.xml`；`.cod` 产物同样取 cod 程序集命名 `MathLib.cod → MathLib.cod.xml` 以免歧义，最终以实现时 CodAssemblyNaming 输出为准，规范不变：**与产物同名再加 .xml**）。
- 写出位置：产物所在目录（exe/library/cod 三种 `-f` 输出一致）。
- 编码 UTF-8；文本经标准 XML 转义（`& < > "`）。

### 5.2 Member name（.NET DocID 风格）

| 成员种类 | 前缀与格式 | 示例 |
|----------|------------|------|
| class/interface/enum/delegate | `T:<Ns.><Type>` | `T:System.Collections.List` |
| 字段（含枚举成员） | `F:<Ns.><Type>.<Field>` | `F:System.Boolean.True` |
| 属性 | `P:<Ns.><Type>.<Prop>` | `P:App.Point.X` |
| 事件 | `E:<Ns.><Type>.<Event>` | `E:App.Button.Click` |
| 方法/构造 | `M:<Ns.><Type>.<Method>(<全名参数表>)`；构造固定名 `#ctor`；无参省略括号 | `M:App.Point.#ctor(System.Int32)` |

类型拼写规则：

- 关键字别名映射系统全名（复用现有 systype 映射）：`i32/int → System.Int32`、`string → System.String`、`bool → System.Boolean`…
- 泛型按 .NET 约定反引号+元数：`List<int> → List`1`；泛型方法实参化后的单态体仍按声明泛型计（与 .NET 一致）。
- 函数类型映射到内建委托家族全名：`(A,B)->R → System.Func{A,R}` 的 DocID 拼写 `System.Func`2`。
- 重载靠参数表区分（与 .NET 相同）；返回值不参与区分。
- 全局函数（无类型容器）：`M:<函数名>(…)`（命名空间为空则容器段缺省）。

### 5.3 生成开关

| 入口 | 形态 | 默认 |
|------|------|------|
| coproj `[options]` | `doc = true/false` | false |
| CLI | `cocoa build -p foo.coproj --doc` / `cocoa hello.co --doc` | 不开 |
| 优先级 | CLI > coproj（沿用现有构建选项覆盖顺序） | — |

默认关的理由：存量产物目录快照类测试不受扰动；对齐 .NET SDK（`GenerateDocumentationFile` 默认亦为 false）。

### 5.4 发射接线

`Compilation.Emit` 家族增加文档写出分支：收集 compilation 公开符号面（全局函数 + 类成员 + 枚举 + delegate），逐符号查 `DocumentationText` → 解析回结构化字段 → 按 DocID 排序稳定输出。无任何文档时不产生空 members 文件（跳过写出，减少噪音）。

## 6. `.cod` 内嵌 docs 段

### 6.1 段格式

manifest 之后、checksum 之前新增：

```
(docs
    (doc "T:System.Math" "数值数学函数集。")
    (doc "M:System.Math.Abs(System.Int32)" "<summary>返回绝对值。</summary>\n<param name=\"value\">输入值。</param>")
)
```

- 条目 key = DocID（§5.2 同一实现，单一真相）；value = 规范化原文，换行以 `\n` 转义成单行字符串，引号/反斜杠按既有 cod 字符串编码转义。
- 无文档的程序集整段省略。

### 6.2 序列化改动

| 处 | 内容 |
|----|------|
| `CodProgram` | 加 `ImmutableDictionary<string, string> Docs` 字段 |
| `CodSerializer.Write` | manifest 段后写 `(docs …)`（约 :147 前） |
| `CodSerializer.Load/Read` | 段循环 switch 加 case（:1478-1518） |
| 版本策略 | Version 保持 1；旧库无 docs 段照常可读（读侧可选段），但**带 docs 的新库旧读侧拒载**——SDK 重建为硬前置（tools/build-sdk.cmd，提交同步刷新 libs\System.Core.cod） |

### 6.3 消费回填

`EmitCocoa` 构造 CodProgram 时填入 Docs（key 取各符号 DocID）；`.cod` 读侧创建符号处（CodSerializer.cs:1857 一带 `new FunctionSymbol(...)`）按 DocID 查表回填 `Symbol.DocumentationText`。由此 stdlib 符号在 REPL / IDE 中自带文档，无需源码。
