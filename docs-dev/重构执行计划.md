# 重构执行计划

> 状态标记：⬜ 未开始 / 🔄 进行中 / ✅ 完成 / ⏭️ 跳过
> 规则：每个步骤完成后**更新本文档进度表并单独提交**（commit message 前缀 `refactor(plan)`）。
> 硬性约束：
> 1. 全程不改外部契约：`cocoa` CLI 参数、`.coa` 格式、`.cocproj`/`.cosln` 格式、方言 API 面（带前缀类型名保持）
> 2. 每阶段独立 PR（本仓库为单人主干流，落地为独立 commit），可回滚；改名（阶段 2）与去重（阶段 3）绝不混合
> 3. 每阶段验收：`build.cmd` 全绿 + 黄金基线一致 + 警告数不增（P0 警告棘轮自动守护）
> 4. 阶段 1 的 bug 修复必须先于阶段 3 的去重，否则两份副本要修两次

## 已确认的设计决策

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 前端 Cocoa/CSharp 重复 | 走"共享骨架 + Source Generator 生成语法节点"路线（兼容多语言扩展意图），Parser 不合并（已实质分化） |
| 2 | 解释器（Evaluator） | 提升为独立解释器后端项目，与 IL/Native 同构走 `Register()` 模式 |
| 3 | 项目/命名空间改名 | 全面改名，物理程序集名对齐逻辑命名空间 |
| 4 | 解决方案文件 | 只留 `.slnx`，删除 `.sln` |
| 5 | 单文件文件夹 | 按功能归属归位（Compilation 吸收散文件、IO 并入 Text、MetadataReader 改名 Emit\IL） |

```
│   ├── Lowering\      4 文件
│   ├── Serialization\ 原 CocoaAssembly\，命名空间统一 .Serialization
│   └── Frontend\      阶段 3 新增：LexerBase/ParserBase/BinderBase/节点描述 + 生成器
├── Cocoa.CodeAnalysis.Cocoa\      ← 原 Cocoa.Core.Cocoa
├── Cocoa.CodeAnalysis.CSharp\     ← 原 Cocoa.Core.CSharp

└── Cocoa.Tests\
```

## 阶段 3：前端"共享骨架 + 生成节点" ⬜（3 个子 commit）

新增共享项目 `Cocoa.CodeAnalysis.Frontend`（两语言共同引用，只有词汇表注入点）：
- 3a 语法节点 Source Generator：83 对逐字相同节点收敛为一份描述文件，生成双方言带前缀类型；Green 工厂（1,791/1,714 行）同理由生成器产出；净删 ~7,000 行
- 3b Lexer 泛型基类 `LexerBase<TSelf, TKind>` + 关键字表注入；三枚举 SyntaxKind 一致性收口 + Debug.Assert 测试
- 3c Binder 提取 `BinderBase`（Declarations/Expressions/TypeResolution 上提，语言子类只 override 分化）；Parser 共享扫描/错误恢复/优先级爬坡提取 `ParserBase`（Parser 本体不合并）
- 新语言接入成本从此 = 词汇表 + Parser 差异，不再复制 93 文件
