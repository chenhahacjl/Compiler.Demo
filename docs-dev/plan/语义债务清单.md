# 语义债务清单（定夺类，非 bug）

> 阶段 5.2 产物。这些是**设计上的已知偏差**：当前行为经过测试验证、可工作，但与"理想语义"
> 或行业惯例有差距。每项列出代码事实、影响面、可选方向；**修不修、何时修需要定夺**，
> 不属于正确性 bug（正确性问题已由阶段 1 修完）。
>
> 约定：任何一项若决定"维持现状"，在本文件标注理由即可销账；若决定"要修"，先在
> `docs-dev/重构执行计划.md` 立项再动代码。

## D1. 重载解析无转换计分

**代码事实**：候选过滤只做**精确签名匹配**（`Bound/BoundScope.cs:143 SameSignature`——元数 +
逐参数类型/out/ref 全等）；构造重载按元数解析（阶段 1b/B10）。无 C# 式"转换质量"计分
（identity < 隐式收窄 < 装箱），无 better-candidate 比较。

**影响**：`f(1.0)` 面对 `f(int)` 与 `f(long)` 直接"无完全匹配"报错，而不是选更近者；
新增隐式转换规则时行为不可组合。

**可选方向**：① 维持现状（语言规范明确"仅精确匹配"最简单，文档写明即可）；② 引入两级计分
（完全匹配 > 数值收窄），改动集中在 Binder 调用解析一处，双方言同步改（漂移测试兜底）。

## D2. CFG 对 try 是黑盒

**代码事实**：`ControlFlowGraph.cs:110/201` 把 `TryStatement` 当叶子语句收进 block
（`_statements.Add(statement)`），try/catch/finally 不展开——无 catch 分支块、无异常边、
finally 不参与可达性。

**影响**：基于 CFG 的分析（可达性、定值分析、将来可能的死代码检查）对 try 体内容失明；
`catch { return; }` 之类的不可达路径检测不到。

**可选方向**：① 维持现状（当前无 CFG 消费方依赖 try 精度）；② try 展开为 success/catch/finally
三个区域 + finally→出口/异常两类边。注意双方言 Bound 节点同构，CFG 是共享层，改一处即两方言生效。

## D3. 诊断无 ID、措辞散布

**代码事实**：`Diagnostic` 仅有 `{IsError, IsWarning, Location, Message}`
（`Diagnostic/Diagnostic.cs`）；无 DiagnosticCode/Descriptor/Severity 分级；消息是各 Binder/Parser
调用点的内联字符串（同一类错误存在多种措辞变体，含中英混排）。

**影响**：无法按 ID 过滤/升级/本地化；`--nowarn` 类 CLI 能力没有挂钩点；文案一致性靠人肉。

**可选方向**：① 维持现状（测试以子串断言消息）；② 最小版：加 `string Code { get; }`（如
`COC1001`）与静态描述符表，CLI 加 `--nowarn:CODE`；③ 完整 Roslyn 式 Descriptor + 本地化（重，
不建议近期做）。注意：加 Code 属公开行为面（诊断输出格式变化），与外部契约清单联动。

## D4. 非虚方法也走 vtable 间接分派

**代码事实**：Native 对象模型 `NativeObjectModel.cs`——对象头 `[0] vtablePtr`，
vtable 为 `[typeId][方法指针数组]`，**所有**类方法（含非虚）都占槽经 vtable 间接调用；
IL 语义中 `call`（非虚）应直接绑定、`callvirt` 才走虚表。

**影响**：非虚调用多一次内存间接寻址（性能，非正确性）；语义上 sealed/nonvirtual 方法无法被
AOT 直接内联绑定。测试覆盖的行为正确，仅偏离 IL 性能模型。

**可选方向**：① 维持现状（实现统一、无需区分 call/callvirt）；② 非虚方法直接 `Call`
LirFunction 地址，仅虚方法占 vtable——需要 LirToAssembler 调用侧区分 IsVirtual，改动中等，
收益是热路径调用与内联门槛。

## D5. BuiltinFunctions 多表人肉同步

**代码事实**：`Symbols/BuiltinFunctions.cs` 内 `_specs` 表（§68）+ 每个内建一个
`public static readonly FunctionSymbol`（§97 起）+ `BuiltinKind` 枚举；三个后端各自实现
（`Cocoa.CodeGen.IL/IlFramework.cs`、`Cocoa.CodeGen.Native` MirToLir.Builtins、
`Cocoa.CodeGen.Interpreter` Evaluator.Calls）+ REPL/分类等处也有按名分派。新增一个内建要改
**≥6 处**，漏一处只能靠 `BuiltinCoverageTests` 类测试兜底。

**影响**：扩展成本高、遗漏风险；属于阶段 1a 已确认"不阻塞"的结构债。

**可选方向**：① 维持现状（内建集已稳定）；② 单表化：`BuiltinSpec` 增加 kind→后端实现标记，
各后端只补实现回调，声明/符号/枚举由 spec 单点生成（**手写单点**，不引入源生成器——见设计原则）。
